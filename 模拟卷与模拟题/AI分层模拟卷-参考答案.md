## 第 1 题（基础题）：定义 AI、举两个应用、析一项局限

人工智能是让机器表现出类人智能行为的技术——能感知环境（听懂语音、看懂图像）、从数据中学习规律，并据此做出判断、预测或生成内容，用来完成通常需要人类智力才能完成的任务。

日常应用一：**语音助手**（如手机语音唤醒、智能音箱）。它把人说的话转成文字、理解意图，帮人查天气、设闹钟、控制家电，解放双手。应用二：**推荐系统**（如短视频、购物 App 的信息流）。它根据历史行为学习每个人的偏好，从海量内容中挑出用户可能感兴趣的，节省筛选时间。

以推荐系统为例分析局限：它存在**"信息茧房"与偏见放大**的问题。推荐算法为了提高点击率，会不断推送与用户既有兴趣相似的内容，导致视野越来越窄；同时用户的每次点击又被算法学去、进一步强化这种倾向，形成自我加强的循环。长期后果是观点极化、接触不到多元信息，还可能被诱导沉迷。此外它依赖收集大量个人行为数据，也带来隐私风险。（约 300 字）

**评分要点**：定义须包含"感知/学习/决策（或生成）"中至少两项；两个应用各说清"帮人做什么"；局限须分析成因或影响，只写名词（如"隐私"两字）不得分。

## 第 2 题（基础题）：图灵测试及其局限

图灵测试的做法是：一位人类评委通过文字与两个看不见的对象自由对话，其中一个是真人、一个是机器；如果多轮对话后评委无法可靠分辨谁是机器，就认为这台机器通过了测试。它的判定依据是**外在的对话行为**——图灵主张与其争论机器"能不能思考"这种难以定义的问题，不如看它的行为能否与人区分。

但图灵测试不能完全等同于智能的判定标准，核心问题在于**"表现得像"不等于"真正理解"**。其一，机器可以靠话术骗过评委：转移话题、装傻卖萌、模仿人类的拼写错误，都能提高"像人"的程度，却与智能无关；历史上的 ELIZA 只用简单的模式匹配就让不少人误以为它能理解。其二，测试只考察语言对话这一个维度，而智能还包括感知、行动、规划等；其三，它以"像人"为标准，可 AI 可以在不像人的方式下很有用（如下棋、蛋白质预测），也可能像人却肤浅。哲学上塞尔的"中文房间"进一步质疑：即使完美通过测试，符号操作本身是否构成理解仍然存疑。（约 300 字）

**评分要点**：说清"评委—真人—机器、文字交流、无法分辨即通过"三要素；局限至少答出"行为≠理解"并有展开（ELIZA/中文房间/话术欺骗任一皆可）。

## 第 3 题（基础题）：主流神经网络类型与 Transformer 核心组件

主流神经网络类型包括：**多层感知机 / 全连接网络（MLP）**，适合表格类数据；**卷积神经网络（CNN, Convolutional Neural Network）**，利用局部连接与权重共享处理图像；**循环神经网络（RNN）及其改进 LSTM/GRU**，靠隐状态逐步传递记忆来处理序列；以及 **Transformer**，用注意力机制处理序列，是现代大语言模型的基础架构。

构建 Transformer 及现代语言模型依赖的核心组件：
1. **文字如何表示**——先用**分词器（Tokenizer）**把文本切成 token，再通过**词嵌入（Embedding）**把每个 token 映射为稠密向量，使语义相近的词向量彼此接近；
2. **顺序如何体现**——注意力本身不感知先后，需要额外加入**位置编码（Positional Encoding）**注入词序信息；
3. **不同位置的内容如何建立联系**——靠**自注意力机制（Self-Attention）**：每个词生成 Query/Key/Value 向量，用 Q 与所有位置的 K 计算相关性权重，再加权汇总 V，让每个词直接"看到"全句；多头注意力并行捕捉多种关系；
4. **信息如何反复加工**——每层还有**前馈网络（FFN）**做逐位置深加工，配合**残差连接与层归一化**保证深层网络可训练；如此堆叠数十层，最后由输出层预测下一个 token。（约 300 字）

**评分要点**：网络类型至少列出 3 类且含中英名；组件须覆盖"表示（token/embedding）、顺序（位置编码）、联系（自注意力）"三问，缺一酌情扣分。

## 第 4 题（前沿题）：AI Agent 与聊天机器人的区别、案例与风险

AI Agent（智能体）是以大模型为"大脑"、能围绕一个目标**自主循环工作**的系统：它先理解目标并拆解步骤，再调用工具（搜索、代码执行、读写文件、调用软件接口）获取信息或执行操作，观察每一步的结果，根据反馈调整下一步，直到完成任务。

与普通聊天机器人的主要区别：聊天机器人是**一问一答、只输出文字**，回答完当前问题就结束；Agent 则**能行动、能多步、能纠错**——它可以执行外部操作而不只是给建议，可以连续几十步推进一个任务，发现出错还会重试或换路。一句话：聊天机器人"会说"，Agent"会做"。

应用案例：**自动化研究助手**。任务目标是"调研某行业近年的发展并写成报告"。执行步骤：拆解出要回答的子问题 → 多轮调用搜索引擎检索资料 → 打开并阅读几十个网页 → 交叉比对数据、剔除矛盾信息 → 汇总成带引用来源的结构化报告。使用的工具是搜索与网页浏览，最终交付一份可溯源的报告。

主要风险：**错误的连锁放大**。Agent 每一步都可能出小错（检索到不实信息、理解偏差），多步执行会让错误累积甚至相互放大，而人不在每步旁监督；若 Agent 还拥有发邮件、付款等真实权限，被恶意网页的"提示注入"劫持后可能执行有害操作。因此高风险动作应保留人工确认。（约 300 字）

**评分要点**：区别须落在"能否行动/多步/纠错"上；案例四要素（目标、步骤、工具、结果）齐全；风险须写出后果链条。

## 第 5 题（前沿题）：多模态 AI 的含义、场景与挑战

多模态 AI 中的"多模态"，指模型能同时处理**多种不同形式的信息**——文本、图像、音频、视频等——并把它们放到统一的语义空间里共同参与理解或生成任务，而不是只擅长其中一种。

应用场景举例：**智能问诊辅助**。患者上传皮肤患处的照片并用文字描述"痒了两周、逐渐扩大"，模型同时利用两种信息：**图像**提供病灶的形态、颜色、边界等视觉证据，**文字**提供病程、症状等上下文；两者结合才能给出比单一模态更可靠的初步判断和就医建议。（类似的还有"拍照搜题+文字追问""看图写文案""视频内容审核"等。）

相比单一模态，多模态 AI 的主要挑战：其一，**对齐难**——图像和文本天然处于不同的表示空间，"猫的照片"和"猫"这个词如何对应起来，需要海量成对数据（如图文对）做对比学习训练，配对数据的获取与质量本身就是瓶颈；其二，**融合后的可靠性**——两种模态信息可能冲突，模型容易被语言先验带偏，出现"看图说话说出图里没有的东西"（视觉幻觉），细粒度信息（数数、小字）也常在特征压缩中丢失；此外，多模态的数据标注与计算成本都显著高于单模态。（约 300 字）

**评分要点**：说清"多"指信息形式且需共同参与任务；案例须写明两种模态各自的作用；挑战至少两项且有机制解释。

## 第 6 题（前沿题）：幻觉的特点、成因与缓解

"幻觉"指大语言模型以**流利、自信、看似专业**的口吻输出**与事实不符**的内容——编造不存在的文献、法条、数据或人物事迹。它的危险在于表面上语法通顺、逻辑自洽、细节丰富，与正确内容在形式上几乎无法区分，用户很容易信以为真。

可能的成因：其一，**生成方式使然**——模型的本职是"预测下一个最可能的词"，它优化的是"文本听起来合理"，而训练目标中并没有"内容必须真实"这一约束，当知识缺失时它仍会按概率补全出最"像真的"的说法；其二，**训练数据与知识时效问题**——训练语料本身含有错误与矛盾信息，且模型知识冻结在训练截止日期，被问及之后发生的事情时只能基于旧知识"推测"，相近的人名、概念还会在统计记忆中互相串线。

缓解策略：**检索增强生成（RAG）**。回答前先从可信知识库或搜索引擎中检索相关资料，把检索到的原文段落放进提示词，让模型"看着资料回答"并标注引用来源。它之所以有效，是因为把"靠参数里的模糊记忆作答"变成了"依据眼前的确切文本作答"——答案有据可查，知识还能随库实时更新，从机制上压缩了模型自由发挥的空间。（约 300 字）

**评分要点**：特点须点出"流利自信但失实"；成因两条须来自不同角度；缓解须解释"为什么能减少错误"，只写名词不给分。

## 第 7 题（编程题·改错题）：Dropout 与评估模式

**(1) 测试代码存在什么问题？**

模型创建后默认处于**训练模式（`model.train()` 状态）**，测试代码没有调用 `model.eval()` 就直接预测。此时 Dropout 层仍按训练行为工作——每次前向传播随机丢弃约 50% 的神经元输出。这会导致：测试结果不稳定（同一批数据两次预测不同）、模型只用"残缺"的网络作答，测出的准确率系统性偏低且不可复现。

**(2) 为什么该状态下两次输出不同？**

训练模式下的 Dropout 在**每次前向传播时都重新随机采样一个掩码**，决定哪些神经元被置零。两次预测采到的掩码不同，参与计算的神经元子集就不同，输出自然不同。而在评估模式下 Dropout 会被关闭（等价于恒等映射），输出才是确定的。

**(3) 修改后的测试代码：**

```python
model.eval()                      # 关键:切换到评估模式,关闭 Dropout 的随机行为
correct = 0
total = 0
with torch.no_grad():             # 关闭梯度计算,省显存、加速
    for x, y in test_loader:
        outputs = model(x)
        _, predicted = torch.max(outputs, 1)
        total += y.size(0)
        correct += (predicted == y).sum().item()
accuracy = correct / total
```

**(4) 测试完成后若还需继续训练，应执行什么操作？**

调用 **`model.train()`** 把模型切回训练模式，恢复 Dropout（以及 BatchNorm 等层）的训练行为；否则接下来的训练将在 Dropout 失效的状态下进行，正则化效果丢失。

## 第 8 题（编程题·构建 CNN）：填空答案

尺寸推导：输入 3×32×32 → Conv1(3→8, 3×3, padding=1) 尺寸不变 → 2×2 池化 → 8×16×16 → Conv2(8→16) → 池化 → **16×8×8**，展平后 16×8×8 = **1024**。

| 空 | 答案 | 说明 |
|---|---|---|
| ① `in_channels` | `8` | 第二层的输入=第一层的输出通道数 |
| ② `out_channels` | `16` | 题目要求 8 通道 → 16 通道 |
| ③ 全连接输入维度 | `16 * 8 * 8`（=1024） | 通道数 × 两次池化后的特征图 8×8 |
| ④ 第二层前向传播 | `self.conv2(x)` | 与第一层同构:`x = self.pool(F.relu(self.conv2(x)))` |

完整代码：

```python
self.conv2 = nn.Conv2d(
    in_channels=8,        # [①]
    out_channels=16,      # [②]
    kernel_size=3,
    padding=1
)
self.pool = nn.MaxPool2d(2)
self.fc = nn.Linear(16 * 8 * 8, 10)   # [③]

def forward(self, x):
    x = self.pool(F.relu(self.conv1(x)))
    x = self.pool(F.relu(self.conv2(x)))   # [④]
    x = torch.flatten(x, 1)
    x = self.fc(x)
    return x
```

**常见错误**：③ 写成 `16*16*16`（忘了第二次池化）或 `8*8*8`（用错通道数）；④ 写成 `self.conv1(x)`（复制第一层忘改名）。
