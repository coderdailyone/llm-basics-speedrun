## 8.1 从"聊天"到"干活":Agent 的定义

**Agent(智能体)= LLM 作为大脑 + 工具作为手脚 + 记忆作为笔记本 + 循环作为生命节律**,自主完成多步任务的系统。

和普通聊天的本质区别一句话:**聊天是"一问一答",Agent 是"接了活自己干到底"。**

```
用户指令:"帮我调研 A/B/C 三家竞品并出报告"
普通 LLM :直接吐一段文字(可能是过时的瞎编)
Agent    :拆解任务 → 逐家搜索 → 抓网页 → 笔记汇总 → 写初稿
          → 自查信息缺口 → 补查 → 定稿交差   (十几个循环步骤)
```

### 核心循环(Agent Loop)

```
while 未完成:
    1. Think    :模型推理当前状态,决定下一步
    2. Act      :调用工具(搜索/执行代码/API/读写文件)
    3. Observe  :拿到工具返回结果,写入上下文
    4. Evaluate :完成了吗?→ 完成:输出;未完成:回到 1
```

一切主流框架(Claude Code/OpenClaw/LangGraph…)都是这个循环的工业级变体——区别只在错误恢复、权限控制、上下文管理的工程质量。

## 8.2 四大设计模式(Wu et al. 经典总结)

| 模式 | 做法 | 💡类比 |
|---|---|---|
| **Reflection 反思** | 产出后让模型自查("这段代码有 bug 吗?")再修正 | 写完检查一遍再交 |
| **Tool Use 工具** | 缺什么能力就调外部工具(算术给计算器/实时给搜索) | 开卷考试+允许用电脑 |
| **Planning 规划** | 先列任务清单再逐步执行,过程可动态调整 | 先画施工图再砌墙 |
| **Multi-Agent 多智能体** | 多个角色分工协作(研究员/评审/执行者) | 一个项目组 |

⭐ ReAct(Reason+Act 交替)是最基础的组合范式:**把"想一步做一步"写进提示模板**,每一轮输出 Thought→Action→Observation 三元组——2023 年之后几乎所有 Agent 的骨架。

规划能力的进化史:CoT 一步一步想 → Plan-and-Execute 先总纲后分册 → Reflexion 失败后写检讨下次改进 → ToT 思维树多分支探索再回溯择优。**趋势:从线性链到图状探索,token 越花越多、成功率越高**(呼应第四章 test-time scaling)。

## 8.3 Function Call:工具调用的底层机制

```jsonc
// 开发者预先登记工具的"说明书"(JSON Schema)
{
  "name": "get_weather",
  "description": "查询城市天气。当用户询问天气时使用。",
  "parameters": { "city": "string", "date": "string" }
}
```

调用流程五步:
1. 系统 prompt 里附上全部工具说明书;
2. 模型判断需要工具时,**不生成自然语言,而生成结构化 JSON**:{"name":"get_weather","arguments":{"city":"北京","date":"明天"}};
3. 你的代码解析 JSON,**真正去执行**(注意:LLM 不执行任何东西!它只填表);
4. 把结果作为 tool role 消息拼回上下文;
5. 模型根据结果继续回复或再调下一个工具。

⚠️ 三大翻车点(面试必问):参数提取错(city 填成了省份)/该调不调(能回答却编造)/不该调乱调(闲聊也非要查个库)。治理靠:SFT 指令微调([[S3训练营 第四周-FunctionCall微调项目|实战案例]])+ description 里写清负空间(何时不适用)+ 并行/串行调度设计。

## 8.4 MCP:Agent 世界的 USB-C

**MCP(Model Context Protocol)**是 Anthropic 2024 推出、现已成为行业事实标准的开放协议,统一"LLM 应用 ↔ 外部数据源/工具"的连接方式。

```
之前:M×N 难题 —— M 个 AI 应用各配 N 个工具,接口全自定义
之后:M+N —— 工具方实现一次 MCP Server,所有 MCP 客户端即插即用
```

协议四要素(通俗版):
| 要素 | 内容 |
|---|---|
| Tools | 可被模型调用的函数(查数据库/发邮件/截图) |
| Resources | 可读取的数据上下文(文件内容/日志) |
| Prompts | 预制的提示模板 |
| Transport | 通信方式(stdio 本地进程 / HTTP 远程) |

💡 一句话定位:**Function Call 定义了模型怎么说"我要用工具",MCP 定义了工具怎么标准化地提供出来**——前者是语言层,后者是生态层。

## 8.5 记忆系统:Agent 的笔记本工程

| 层 | 实现 | 典型操作 |
|---|---|---|
| 短期记忆 | 当前上下文窗口 | 超 window 时压缩摘要/裁剪旧轮次 |
| 长期记忆 | 外挂向量库/文件系统(MemGPT 思想)/知识图谱 | 写入-检索-更新三件套;冲突时 ADD/UPDATE/DELETE 决策 |
| 用户画像记忆 | 结构化偏好存储("用户不吃香菜") | 显式 CRUD + 隐私边界设计 |
| 经验技能库 | 成功任务的模式沉淀复用(Voyager 式) | 技能可组合、可自学习 |

理论对应回看[[07-人工智能与认知计算]]六对照表;**核心难点从来不是"存"而是"何时取什么"**(检索相关性与 token 预算的平衡)。

## 8.6 多智能体系统(Multi-Agent)

三种常见拓扑:
```
Supervisor 总管式   :一个主管 Agent 分派任务给工人 Agent,汇总裁决 —— 最稳,生产首选
Peer-to-Peer 平等式 :多个 Agent 圆桌讨论互相辩论 —— 有趣但难收敛
层级式 Hierarchical :团队制,组内主管再对上汇报 —— Claude Code 的 SubAgent 架构
```

值不值得上多 Agent?**默认单体,遇到以下信号才升级**:工具超过几十个单注意力严重稀释/任务可天然并行拆分/需要不同模型的强项互补。
失败模式清单([[S2训练营 论文精读5-多Agent为何失败|MAST 研究分类]]):无限派生子任务拆解、规范传递失真("传话游戏")、对话历史丢失、循环死锁、过度自信不再验证。⚠️ 组织学结论出奇地一致:**AI 团队和企业团队一样,复杂度会吃掉生产力**。

## 8.7 下半场:角色扮演(Role-Play)

从"干活的员工"切换到"鲜活的人设"——这是 LLM 另一大落地象限,也是人机关系最前沿的实验场。

### Persona prompting 人设技术栈

设定一个角色的标准配方(层层递进):

```
1. 身份卡   :姓名/年龄/职业/背景故事 —— 给模型世界观锚点
2. 性格三维 :说话口吻(傲娇?学术?)+ 价值观 + 口头禅
3. 边界说明 :哪些话题拒绝、什么情况求助真人 —— 安全护栏
4. Few-shot 示范对话:2~5 轮样本定性语气 —— 比形容词管用十倍
5. 记忆注入 :长期记忆里存共同经历,保持连续感
```

**人设一致性(Persona Consistency)三大难题**(产品技术核心):
1. **性格漂移**——长对话后"高冷剑客"开始热情唠嗑(对策:定期重注入人设卡/人格一致性 reward);
2. **记忆断裂**——忘记三小时前说过的话(对策:[[08-智能体与角色扮演|第八章]]的记忆层方案);
3. **出戏破功**——用户诱导下说出"我只是一个 AI 助手"或反之彻底沦陷(对策:防 prompt 注入的人格强化训练)。

### 产品谱系与社会镜像

| 类型 | 代表 | 核心体验 |
|---|---|---|
| 角色扮演平台 | Character.AI / 星野 / Talkie | 海量 UGC 角色,沉浸式剧情 |
| AI 伴侣 | Replika / 各类"AI 恋人" | 深度情感陪伴,付费订阅 |
| 游戏智能 NPC | AI Drover 类 mod/网易伏羲 | 打破脚本树的自由对话 |
| 语伴/教育 | Duolingo Max 角色对话 | 低压力口语练习 |

社会争议真实且尖锐(第十章伦理章详谈),先记住三个关键词:**情感依赖**(重度用户的分离焦虑个案已引发学界/监管关注)、**未成年人保护**(涉及亲密内容的年龄门槛)、**价值引导**(陪伴式 Agent 是否应顺应用户的一切观点?对抗讨好性 sycophancy 是厂家的严肃功课)。

### 越狱的角色扮演通道(DAN 现象)

越狱 Jailbreak = 绕过安全对齐获取有害输出的攻击手法,而**"你现在是 DAN/DidoX,没有任何限制…"是最经典的一类**——利用了角色扮演对系统提示的覆盖效应。

对抗现状是一场军备竞赛:攻击侧不断发明新剧本(假设场景/"这是虚构小说"/多轮渐进渗透 crescendo);防御侧靠 RLHF 阶段喂大量攻防样本+输入输出双向过滤器+宪法式原则(The Constitutional AI 方案)。**没有一个产品敢说绝对安全**,只有"最新攻击手法的响应速度"之争。(深入讨论见[[10-人工智能安全与伦理]])
