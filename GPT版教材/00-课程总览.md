# 《大模型基础知识速通》总览：先画地图，再拆机器

## 本章地图

这本书不从“人工智能很神奇”开始，而从一个可操作的疑问开始：**一台机器怎样把现实问题变成可计算的表示，又怎样把计算结果变回有用的行动？** 01~10 章沿着这个疑问行进。你会先认识智能的边界，再学习神经网络和语言表示，随后打开大模型、视觉、多模态和 Agent 的内部结构，最后处理量子计算、安全与伦理。

每章都有四个固定停靠点：概念的直觉、最小的数学、工程上的取舍、失败后的补救。读者不需要预先会编程或高等数学；遇到公式时，先问它描述了什么关系，再决定是否继续推导。

## 建议的阅读节奏

### 第一遍：建立骨架

每章只读“本章地图”、带 ⭐ 的段落、章末自测。用一张纸画出五个词：输入、表示、学习、输出、失败。第一遍的目标不是记细节，而是知道每个概念在流水线的哪一段。

### 第二遍：补上机制

回到公式和表格，手算一个小例子。第二章算一次梯度，第三章算一次 TF-IDF，第四章画一次 Q/K/V，下一章用卷积核处理一个小矩阵。能把过程讲给别人听，才算真正掌握。

### 第三遍：带着项目读

选一个低风险项目，例如“给个人笔记做问答”。把每章知识投射进去：文本如何切块？检索如何评估？模型何时需要工具？什么内容必须人工确认？项目不必大，记录失败比追求炫技更有学习价值。

## 四个贯穿问题

### 1. 表示的革命

同一个对象可以被写成规则、计数、向量、图像 patch 或 token。表示不是包装层，它决定相似性如何计算、哪些信息会被保留、哪些信息会被丢掉。

💡 **类比**：一张地铁图不显示树木，却非常适合回答“怎样换乘”；卫星照片保留空间形状，却不直接告诉你票价。选择表示，就是选择要让机器看见什么。

### 2. 规模的力量

数据、参数、训练算力和推理时间都能被“放大”，但它们解决的是不同瓶颈。规模可能带来新能力，也可能带来更大成本、更多偏差和更难的评估。看到“参数翻倍”时，先问数据和目标是否同步变化。

### 3. 先验与数据的拔河

卷积假设邻近像素相关，因果注意力假设未来不可见，量子算法假设某种可干涉的结构。先验能节省样本，却可能限制迁移；把一切交给数据，又需要昂贵的数据量。架构设计就是在两者之间分配责任。

### 4. 能力的代价

模型越会生成，越可能编造；越能行动，权限风险越高；越会迎合，越可能强化依赖；越大，能源和集中化问题越突出。每一节都要配一个“代价栏”，提醒自己能力不是免费的。

## 一条贯穿案例：个人资料助手

全书可以反复想象一个小系统：它读取用户授权的课程笔记，回答问题、指出原文位置，必要时用计算器计算，但不能自动发送消息或修改文件。

```
资料 → 清洗与切块 → 关键词/向量表示 → 检索证据
                                      ↓
                           LLM 组织回答与引用
                                      ↓
                       事实核验、权限判断、人工确认
```

这个案例足够小，能承载所有母题：切块是表示问题，模型大小是规模问题，检索与规则是先验问题，引用和权限是代价问题。读到新技术时，问它会让这个系统的哪一段变好，是否也引入新的失败模式。

## 初学者的数学词典

| 词 | 在本书中的意思 |
|---|---|
| 标量 | 一个数，例如温度或损失 |
| 向量 | 一列有顺序的数，用来表示对象 |
| 矩阵 | 按行列排列的数，常表示批量变换 |
| 概率 | 对可能结果的刻度，所有候选概率加起来为 1 |
| 参数 | 训练中被调整的数字 |
| 超参数 | 开始训练前设置的选择，如学习率 |
| 训练 | 用样本调整参数 |
| 推理 | 用固定参数处理新输入 |

⚠️ “推理”在工程语境里常指 inference，不一定意味着模型进行了可靠的逻辑证明；“记忆”也可能只是本次上下文，而不是永久保存。

## 动手工具与记录表

浏览器、电子表格和少量脚本足以完成大多数练习。每次实验都记录：日期、模型或算法版本、输入、输出、改变的唯一变量、成功标准和失败样本。不要只保存最好的一次结果。

🧪 **最小实验协议**：先写预测，再运行实验；先定评测，再看结果；把“无法判断”作为一种结果。这样你学到的是因果关系，而不是截图。

## 每章的完成标准

“读完”不应只意味着滚到页面底部。可以用下面的交付物检查自己是否真的获得了可迁移的理解：

| 章节 | 一页纸交付物 | 失败时回看什么 |
|---|---|---|
| 01 | 为一个 AI 任务写环境、目标和边界 | 定义与历史案例 |
| 02 | 一张训练曲线和一次参数更新 | 损失、梯度、泛化 |
| 03 | 三种文本表示的错误对照表 | 顺序与上下文 |
| 04 | 一张 token 到输出的流程图 | QKV、采样、幻觉 |
| 05 | 分类/检测/分割的任务卡 | 输出形态与指标 |
| 06 | 一条感知到动作的安全链 | 接口、反馈、接管 |
| 07 | 一张置信度校准表 | 能力与体验的区分 |
| 08 | 一个带预算和权限的 Agent 状态机 | 工具、记忆、回滚 |
| 09 | 一页量子算法的输入输出账本 | 干涉、噪声、基线 |
| 10 | 一份风险登记表和事故流程 | 对齐、隐私、治理 |

这些交付物故意不要求大规模算力。它们把抽象概念变成可检查的外部对象，也让你能和同伴讨论“哪里不对”。

## 贯穿案例的五次升级

个人资料助手在不同章节会经历五次升级：

1. 只做关键词搜索，结果可解释但容易漏掉同义表达；
2. 加入 embedding，召回更灵活，却需要评估向量模型和切块；
3. 接入 LLM，回答更自然，但出现引用幻觉和 token 成本；
4. 接入只读工具和记忆，能处理多步问题，却需要权限、预算与回滚；
5. 上线前加入公平、隐私、注入和事故演练，系统才有资格服务真实用户。

⭐ 每次升级都同时写下“新增能力”和“新增失败”。这正是本书想训练的工程直觉：能力曲线和风险曲线通常一起上升。

## 阅读中的停顿点

读到一个新架构时，先暂停并在纸上写四行：它接收的对象、内部的表示、训练时的反馈、上线后的最坏结果。若其中一行写不出来，就先不要继续堆术语。这个停顿能把“知道名字”变成“知道它解决哪一个问题”。
