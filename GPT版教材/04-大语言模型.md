# 第四章 大语言模型：从一串 token 到一次回答

## 本章地图

把一次聊天想成工厂流水线：Tokenizer 切原料，Embedding 贴上数字坐标，Transformer 反复交换信息，输出头给词表打分，采样器选择下一个 token。预训练让工厂学会续写，后训练教它遵循指令，推理系统再负责速度、成本和安全。本章沿这条流水线逐站走一遍，并在最后解释为什么“说得像真的”仍可能是幻觉。

## 4.1 生成的最小循环

给模型一段前缀 `x_{1:t}`，它计算下一个 token 的概率：

$$P(x_{t+1}\mid x_1,\ldots,x_t)$$

选出一个 token 后，把它接回前缀，重复计算。停止条件可能是结束 token、达到长度上限或被服务端截断。模型没有先写好一篇答案再发送，而是每一步都根据当前上下文重新决定。

⭐ **核心考点**：next-token prediction 是训练目标，也是生成接口的基本动作；“推理”在这里首先指 inference，不自动意味着可靠的逻辑推导。

## 4.2 Tokenizer：语言的分装规格

字符对人有意义，对神经网络只是输入符号。Tokenizer 把字符串转成整数 id，再由 embedding 表查成向量。一个 token 可能是一个汉字、一个英文词的一部分、空格、标点或代码片段。

### BPE 怎样建立词表

Byte Pair Encoding 从字符或字节开始，统计相邻片段的频率，合并最常见的一对，循环直到达到词表大小：

```
c a t / c a t s / c a r
→ ca t / ca t s / ca r
→ cat / cats / car
```

高频组合变短，生僻词仍可拆成小片段，因此词表能覆盖新词。词表越大，常见词占用的 token 越少，但 embedding 和输出矩阵更大；词表越小，序列更长，注意力开销更高。

中文、数字和代码会产生不同切分。上下文窗口、价格和速度按 token 计算，不按“字数”计算。把一长串数字拆开还可能让算术和比较更难，因为数位结构没有被自然保留。

⚠️ 不同模型的 tokenizer 不兼容。把一个模型的 token 数直接套到另一个模型，成本估算会出错。

## 4.3 Embedding 与位置

Embedding 矩阵 `E∈R^{V×d}` 有 `V` 行，每行是一个 token 的 `d` 维向量。输入 id 只是查表索引，不是数值大小；id=100 并不比 id=20 更“接近”。

注意力需要知道顺序。绝对位置编码给第 `i` 个位置加一个向量；RoPE 则在不同角度旋转 Q、K，使内积自然携带相对距离。位置方案影响长上下文外推，不是可随意替换的小细节。

## 4.4 Transformer 的一层

典型 decoder-only 层可以画成：

```
x ──→ 归一化 ──→ 自注意力 ──→ +x ──→ 归一化 ──→ FFN ──→ +残差
```

### Q、K、V：一次可微检索

给定隐藏状态 `X`：

$$Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V$$

每个位置的 Query 与所有 Key 做内积，得到相关分数，再加权汇总 Value：

$$\operatorname{Attn}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}+M\right)V$$

`√d_k` 把高维点积缩回稳定范围；否则 softmax 容易变成几乎全 0/1，梯度难以学习。`M` 是遮罩，未来位置填负无穷，保证生成时不能偷看答案。

💡 **类比**：你在档案室拿着问题（Q）看索引卡（K），按相关程度取出档案内容（V）。注意力不是硬找一张卡，而是可微地混合多份材料。

### 多头、残差和 FFN

多头注意力把维度分成多个子空间，让不同头学习指代、格式或句法关系。残差连接提供信息和梯度的直通路径。FFN 对每个位置做非线性变换：

$$\operatorname{FFN}(x)=W_2\,\sigma(W_1x+b_1)+b_2$$

注意力更像“搬运和路由”，FFN 更像“变换和存储特征”。MoE 把 FFN 拆成多个专家，每个 token 只激活少数专家，提升总容量而控制每步计算。

## 4.5 为什么主流是 decoder-only

Encoder-only 模型适合理解和分类，encoder-decoder 适合成对的转换，decoder-only 直接以自回归生成作为统一接口。它的优势来自目标与使用方式一致、训练结构简单、历史 KV 可缓存，以及 in-context learning 生态成熟。

这不是说其他范式没用。翻译、检索重排和编码器特征仍可能更适合双向注意力。架构选择应服从任务和成本，不要把产品潮流当成定理。

## 4.6 预训练：用交叉熵压缩语料

预训练把网页、书籍、代码、论文等文本清洗、去重、分片后送入模型，优化：

$$L(\theta)=-\frac1T\sum_{t=1}^{T}\log P_\theta(x_t\mid x_{<t})$$

每个位置都是一次“词表多选一”。要在海量样本上降低损失，模型会学习语法、事实共现、格式和部分推理模式。数据质量、重复率、个人信息、版权和评测污染会随着参数一起留下。

缩放定律描述损失随参数、数据和计算量在一定范围内平滑下降；Chinchilla 类研究提醒，给定算力时，参数和训练 token 需要匹配。它们是经验拟合，不保证任何规模都出现新能力，更不替代真实任务评测。

## 4.7 后训练：教模型“怎样服务”

### SFT：模仿示范

监督微调用高质量指令—回答对，教会模型角色、格式、多轮边界和基本帮助性。它改变行为分布，不等于重新灌输一个完整百科。

### RLHF：用偏好塑形

人类比较回答 A/B，奖励模型学习偏好，再用 PPO 更新策略，同时用 KL 约束避免漂移。它能改善有用、诚实、无害风格，但奖励模型可能被冗长、讨好或表面格式欺骗。

### DPO：直接用偏好对

DPO 不单独训练奖励模型，也不在线采样 PPO，而是让偏好回答相对参考模型获得更高概率。流程简单、适合离线数据，但仍受偏好标注质量影响。

### GRPO：组内相对比较

对同一问题采样一组答案，按组内奖励差异估计优势，减少对独立价值网络的依赖。它常用于推理训练，但“组内更好”不保证绝对正确。

### RLVR：验证器给奖励

数学答案、代码单元测试、形式证明等任务可以用程序验证。RLVR 将主观偏好换成可验证信号，可能鼓励模型延长思考、回溯和自检；开放领域事实仍需要检索和人类判断。

## 4.8 推理时的三个旋钮

### 采样

温度 `T` 改变 logits 的尖锐程度：

$$p_i=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)}$$

低温更稳定，高温更发散；top-k 保留前 k 个候选，top-p 保留累计概率达到阈值的候选。采样只改变选择方式，不增加训练知识。

### 上下文

系统提示、用户消息、工具结果和历史对话会共同占用上下文窗口。长上下文不是无限记忆：注意力成本、位置外推、信息冲突和“中间内容被忽略”都会影响效果。摘要、分层检索和引用可以减少噪声。

### KV Cache

历史 token 的 Key、Value 在生成后不会变化，缓存它们就不必每步重算。新 token 只计算自己的 Q，与缓存交互。缓存显存大致随层数、KV 头数、头维度、序列长度和并发量增长；GQA/MQA、分页管理和量化能缓解瓶颈。

## 4.9 服务工程：速度、价格和可控性

FlashAttention 用分块方式减少中间矩阵读写；量化把权重从 FP16 压到 INT8/INT4；LoRA 冻结主模型、训练低秩增量；投机解码让小模型先起草、大模型批量验证；连续批处理让不同请求共享 GPU。每项优化都有质量、兼容性或实现复杂度的取舍。

## 4.10 幻觉：概率顺滑不等于事实为真

幻觉是流畅、具体、看似自信但错误或虚构的输出。原因包括目标函数只奖励似然，知识分布式存储且边界模糊，训练资料过时或冲突，模型缺少稳定的未知状态，以及问题前提本身错误。

缓解需要分层：RAG 提供外部证据，计算器和代码执行验证可计算结果，结构化输出减少歧义，多次采样发现不稳定，人工审核承接高风险。RAG 也会检索错误资料、产生伪引用，因此来源必须可访问、可核对、带时间和权限。

## 4.11 评估一套 LLM 系统

知识、代码、数学、长上下文和对话偏好需要不同数据集。除了正确率，还应报告校准、拒答质量、延迟、成本、鲁棒性、提示注入抵抗和真实任务完成率。榜单分数是线索，不是交付许可证。

## 🧪 动手实验：把一次回答拆成证据链

固定一个事实问题，分别用低、中、高 temperature 生成三次。将回答拆成最小断言，为每条断言记录来源、是否可核验、token 数和延迟。再加入一个计算器或文档检索工具重做，比较“模型直接说”和“证据后说”的错误类型。
