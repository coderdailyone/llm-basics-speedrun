# 第四章 大语言模型

## 本章地图

本章回答一个具体问题：一段文字怎样变成模型的一串数字，再怎样变回下一段文字？路线是 `文本 → token → 向量 → Transformer 层 → 概率 → 采样`。随后区分预训练与后训练，解释 SFT、RLHF、DPO、GRPO、RLVR，最后讨论上下文、KV Cache、量化、评估和幻觉。读完你应能画出一个 decoder-only 模型的最小结构。

## 4.1 LLM 到底学了什么

大语言模型（Large Language Model, LLM）通常以“给定前文预测下一个 token”为训练任务。输入是 `x1,...,x_t`，模型给出条件分布：

$$P(x_{t+1}|x_{1:t})$$

生成时取一个 token 拼回输入，继续预测，直到遇到结束标记。任务形式很简单，但要在海量文本上降低预测误差，模型必须压缩语法、事实关联、写作格式和部分推理模式。

⚠️ “只是概率接龙”与“拥有像人一样的理解”都是过度简化。它确实优化了概率分布，也确实形成了可复用的内部表示；但概率上的熟练不自动带来事实保证、意图、意识或现实经验。

## 4.2 Tokenizer：模型使用的文字单位

神经网络不直接吃汉字和标点，Tokenizer 把字符串变成 token id。一个 token 可以是一个字、半个词、一个常见词，或代码中的一段符号。不同模型的词表、空格处理和中文切分方式都可能不同，因此 token 数不能简单等同于字数。

### BPE 的训练直觉

Byte Pair Encoding 从字节或字符开始，反复统计相邻片段的频率，把最高频的一对合并，直到达到词表大小：

```
l o w / l o w e r / lowest
→ lo w / lo w e r / lowest
→ low / lower / lowest
```

高频片段变成短 token，生僻词退化为更小片段，所以新词也能表示。词表越大，常见词 token 越少，但 embedding 和输出层更大；词表越小，序列更长，注意力成本更高。

中文、数字和代码会暴露切分差异：一个汉字不一定正好一个 token，数字可能被拆成多个片段，缩进和 Unicode 变体也可能占用额外上下文。API 计费、上下文窗口和吞吐通常都按 token 计算。

## 4.3 从 token 到 logits

```
文本
 ↓ tokenizer
token id: [15496, 11, ...]
 ↓ embedding 查表
向量序列 X
 ↓ 位置编码 + N 层 Transformer
隐藏状态 H
 ↓ 线性 LM Head
logits（词表中每个 token 的分数）
 ↓ softmax / 采样
下一个 token
```

Embedding 矩阵的每一行是一个 token 的向量。位置编码告诉模型顺序；Transformer 层反复做“读取上下文—变换特征”。最后的 logits 不是概率，softmax 才把它们归一化为总和为 1 的分布。

## 4.4 Transformer：一层积木如何工作

现代生成式 LLM 多为 decoder-only。一个 pre-norm 层可抽象为：

```
x → RMSNorm → 多头自注意力 → 加回 x → RMSNorm → FFN → 加回
```

残差连接让原始信息有一条直通路径，归一化控制数值尺度。

### Q、K、V 的拆解

给定隐藏状态矩阵 `X`，三个线性投影得到：

$$Q=XW^Q,\quad K=XW^K,\quad V=XW^V$$

注意力公式为：

$$\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)V$$

`Q` 是当前位置的问题，`K` 是每个位置的索引，`V` 是真正要取回的内容。`QK^T` 计算匹配分数，除以 `√d_k` 防止维度变大后 softmax 过早饱和，`M` 是遮罩。

💡 **类比**：图书馆检索时，你拿着查询词（Q）看书脊索引（K），找到相关书后取出正文（V）。它不是硬查一条，而是按相关度混合多本书，因此可微、可训练。

### 因果遮罩与多头

生成第 `t` 个 token 时不能偷看 `t+1` 之后的答案。把未来位置的分数设为负无穷，softmax 后权重为零，这就是 causal mask。训练时仍可并行处理整句，因为每个位置都使用自己的遮罩。

多头注意力把维度切成多个子空间，每个头可以学习不同关系：指代、句法、格式或长距离主题。推理时许多 Q 头共享 K/V，形成 MQA 或 GQA，降低缓存占用；这是结构先验与工程成本之间的交换。

### FFN 与位置编码

前馈网络通常先升维、激活、再降维：

$$\operatorname{FFN}(x)=W_2\,\operatorname{act}(W_1x+b_1)+b_2$$

它为每个位置做非线性变换，参数量常占大头，可视作知识和特征的存储区。MoE 把 FFN 切成多个专家，由路由器为每个 token 激活少数专家，以较低每次计算换取更大的总容量。

注意力本身对顺序不敏感，必须注入位置。绝对位置向量简单但外推有限；RoPE 让 Q/K 在不同位置旋转，内积自然携带相对距离，成为长上下文模型常用方案。

## 4.5 预训练：把互联网压进参数

预训练语料可能包含网页、书籍、代码、论文和合成数据。典型流程是抓取、去重、质量筛选、个人信息与恶意内容处理，再按 token 打包。训练目标是全序列的交叉熵：

$$L=-\frac{1}{T}\sum_{t=1}^{T}\log P_\theta(x_t|x_{<t})$$

缩放定律观察到，在一定范围内，损失随参数量、数据量和计算量呈平滑幂律下降。Chinchilla 类分析强调：只增加参数而不给足数据，可能不是计算预算下的最优解。它们是经验规律，不是“越大永远越好”的定理。

数据污染、重复、过时事实和版权来源都会进入模型。预训练让模型“知道如何续写”，并不保证它知道何时应该拒答。

## 4.6 后训练：从续写器到助手

### SFT：学习任务格式

监督微调使用“指令—回答”示例，教模型理解用户角色、对话模板、格式和基本帮助性。它主要改变行为分布，不是把所有领域知识重新写入模型。高质量少量样本常比大量重复样本更有价值。

### RLHF：学习偏好

经典 RLHF 包含：收集人类对回答的排序，训练奖励模型，再用 PPO 更新策略，并用 KL 惩罚防止偏离 SFT 模型太远。它能改善有用、诚实、无害等风格，但奖励模型可能被“讨好、冗长和格式化”钻空子。

### DPO：离线直接优化偏好

DPO 直接用“偏好回答/非偏好回答”对优化策略相对参考模型的概率，不单独训练奖励模型，也不运行在线 PPO。流程更简单，适合很多开源微调场景；它仍然继承偏好数据的偏差。

### GRPO：组内比较

GRPO 为同一个问题采样一组答案，用组内相对奖励估计优势，减少对独立价值网络的依赖。它在推理模型训练中常与可验证奖励结合。记忆口诀不是重点，重点是理解：PPO 依赖在线策略与奖励模型，DPO 使用离线偏好对，GRPO 通过组内相对表现省掉部分 critic。

### RLVR：让结果可验

RLVR（Reinforcement Learning with Verifiable Rewards）用单元测试、数学答案或形式验证器提供奖励。奖励更客观，模型可能学会分步思考、回溯和检查。验证器覆盖不到的开放问题仍然需要人类偏好与事实核验。

## 4.7 推理：上下文、采样与 KV Cache

生成时，temperature 对 logits 做缩放：

$$P_i=\operatorname{softmax}(z_i/T)$$

`T<1` 更保守，`T>1` 更分散。Top-k 只保留最高 k 个 token，top-p 保留累计概率达到 p 的最小集合。它们控制多样性，不会修复错误知识。

自回归模型每生成一个 token 都需要读取历史。历史 token 的 Key 和 Value 不变，于是可缓存起来，新 token 只计算自己的 Q，再与缓存交互。KV Cache 让重复计算减少，却让显存随层数、KV 头数、头维度、上下文长度和并发数增长。GQA、PagedAttention、滑动窗口和量化都是围绕这个瓶颈的工程方案。

其他常见优化：FlashAttention 分块计算避免显式保存完整注意力矩阵；量化把 FP16 权重压到 INT8/INT4；LoRA 冻结大矩阵、训练低秩旁路；投机解码用小模型起草、大模型验证；连续批处理让不同长度请求共享 GPU。

## 4.8 幻觉：流利输出的阴影

幻觉是“语言通顺、自信具体，但事实错误或不存在”。结构性原因包括：

1. 训练目标奖励似然，不直接奖励真实；
2. 参数是分布式统计记忆，边界案例会被插值；
3. 训练数据可能错误、冲突或过时；
4. 模型缺乏稳定的“不知道”信号；
5. 用户问题的前提可能本身就是错的。

缓解需要组合拳：RAG 提供可追溯来源，工具调用交给计算器或数据库，结构化输出减少格式歧义，多次采样和一致性检查发现不稳定答案，人工审核承接高风险场景。把“引用”当作装饰也会产生幻觉引用，来源必须真正可访问、可核对。

## 4.9 评估模型而不是只看榜单

知识、代码、数学、长上下文和偏好分别需要不同测试。除了准确率，还要记录拒答质量、校准、延迟、成本、鲁棒性、提示注入抵抗和真实用户任务完成率。基准分数可能受数据污染、提示模板和裁判模型偏差影响。

⭐ **模型选择的顺序**：先定义失败代价和合规边界，再在满足边界的模型中比较质量与成本，最后才考虑参数规模和榜单名次。

## 🧪 动手实验：同题三温度与事实核验

固定一个需要事实回答的问题，分别用 `temperature=0、0.7、1.0` 生成三次。把回答拆成原子断言，用可靠来源逐条标注真、假或无法判断；同时记录 token 数、延迟和重复率。你会看到采样改变多样性，但不能替代知识更新和外部验证。
