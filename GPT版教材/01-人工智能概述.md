# 第一章 人工智能概述

## 本章地图

本章先处理一个经常被忽略的问题：我们到底把什么叫作“智能”？随后用三种研究传统解释 AI 的分歧，沿着两次寒冬回顾方法如何轮换，最后画出 `AI ⊃ ML ⊃ DL ⊃ GenAI ⊃ LLM` 的包含关系。读完后，你应该能看懂一条 AI 新闻中的主语、方法和承诺分别是什么。

## 1.1 “智能”不是单一能力

人会识别朋友、学会骑车、讲故事、制定计划，也会被偏见和情绪影响。把这些现象压成一个分数会丢失很多信息。因此工程上常用“任务定义”：在给定环境中，系统是否能根据观察选择行动，并在目标指标上持续表现？这个定义不要求系统像人，只要求可测量。

图灵在 1950 年提出的模仿游戏把“机器会不会思考”改写成对话行为测试。它适合提醒我们不要迷信内部叙述，却不能测出事实可靠性、身体技能或长期目标。一个系统能通过聊天，不代表它会照顾病人；反过来，自动驾驶也许不擅长闲聊，却能在限定道路上完成复杂决策。

💡 **类比**：温度计很会“测温”，但不懂天气；导航很会“规划路线”，但没有旅行愿望。能力应当按任务和环境描述，避免把一个指标外推成完整人格。

### 狭义、通用与超级智能

| 说法 | 工作定义 | 现实状态 |
|---|---|---|
| ANI 狭义人工智能 | 在限定任务上达到目标 | 搜索、推荐、识别器和今天的大多数模型 |
| AGI 通用人工智能 | 能迁移学习、规划并处理广泛任务 | 没有公认测试或结论 |
| ASI 超级智能 | 在几乎所有认知任务上超过人类 | 假设性讨论 |

⚠️ “大模型=AGI”是把语言流利度当作通用能力。模型在文本任务上表现很宽，但仍会在简单计数、实时感知、持久目标和现实行动上失误。

## 1.2 三大学派：三种答案，三个盲点

### 符号主义：把知识写成可操作的规则

符号主义把智能看成概念、关系和逻辑推演。专家系统用 `如果…那么…` 的规则诊断疾病、配置设备；搜索和规划算法在状态空间中寻找路径。它的优点是过程可检查、样本需求低，适合规则稳定的领域。

它的困难是**知识获取瓶颈**：常识难以穷举，规则之间会冲突，环境一变就需要人手维护。棋盘上的“合法走法”很清楚，开放世界的“通常情况”却没有有限清单。

### 连接主义：让大量小单元共同表示规律

连接主义受神经科学启发，用带参数的网络从例子中调整权重。它不要求工程师逐条写规则，能在视觉、语音、语言中学习分布式表示。反向传播和大规模计算让这条路线在 2010 年代重新成为主流。

代价是内部决策不容易用一句规则解释，数据偏差会进入参数，训练和验证成本较高。

### 行为主义/进化与智能体观点：在环境里看结果

强化学习把系统视为智能体：观察状态、采取动作、得到奖励，再调整策略。它关心“在这个环境中是否做得更好”，不必先规定中间概念。机器人控制、游戏和资源调度常采用此思路。

缺点是奖励设计不当会产生投机行为；模拟环境中的好策略搬到现实可能失效。今天的系统往往是混合体：神经网络负责感知，符号模块负责约束，强化学习负责行动。

⭐ **核心考点**：三大学派不是按年代淘汰关系，而是三种归纳偏置。规则提供结构，网络提供柔性，环境反馈提供目标；真实系统常把三者拼在一起。

## 1.3 两次寒冬与三次复苏

### 第一次寒冬：承诺超过了计算机

1950~60 年代，研究者在小型世界里展示定理证明、对话和棋类程序，乐观地预测很快会出现人类级机器。现实中，内存、算力和数据都太小，搜索空间却呈指数增长。感知机的局限又让神经网络暂时失去关注。

### 第二次寒冬：专家系统的维护账单

1980 年代的专家系统在企业落地，但知识库昂贵、规则脆弱且难以迁移。硬件市场降温、投资撤退，研究称为“AI 冬天”。这次教训是：演示成功不等于生命周期可负担。

### 复苏为何发生

1990~2000 年代，统计学习利用互联网数据，语音和搜索开始商业化；2012 年前后，GPU 并行计算、海量标注数据和更深的网络结构同时成熟，ImageNet 的突破把深度学习推到聚光灯下。2017 年 Transformer 用注意力替代大部分循环，进一步打开语言规模化之门。

⚠️ “2012 年是某个算法凭空诞生的年份”不准确。它是数据、硬件、优化和评测共同到达临界点的结果，也说明规模只有在方法足够稳定时才会转化为能力。

## 1.4 五层包含关系

```
AI 人工智能：让机器完成通常需要智能的任务
└─ ML 机器学习：参数由数据而非规则直接给出
   └─ DL 深度学习：用多层神经网络学习表示
      └─ GenAI 生成式 AI：建模分布并生成新内容
         └─ LLM 大语言模型：以语言 token 为主要输入输出的基础模型
```

这个图是“概念范围”，不是技术优劣榜。一个手写的迷宫搜索属于 AI 但不一定是 ML；随机森林属于 ML 但不是 DL；图像扩散模型属于 GenAI 但不是 LLM。LLM 通常是 GenAI 和 DL 的交集，但某些语言系统也会混合检索、规则和工具。

| 判断问题 | 用来区分什么 |
|---|---|
| 参数是人写的还是从数据学的？ | ML 与非 ML |
| 特征由人设计还是网络自己形成？ | DL 与传统 ML |
| 输出标签还是新样本？ | 判别式与 GenAI |
| 主要处理语言 token 还是图像/声音？ | LLM 与其他生成模型 |

## 1.5 把“能力”拆成四个来源

任何 AI 演示都可以拆成四个来源：**数据**提供例子，**目标函数**定义什么叫做得好，**结构**规定信息如何流动，**算力**让参数有机会被调整。产品阶段还要加第五项：**人类流程**，包括谁审核、谁负责、谁能撤销。

以客服模型为例：历史对话是数据；下一 token 或满意度是目标；Transformer 是结构；GPU 是算力；转人工和审计日志则属于人类流程。只谈参数量，会把最关键的责任环节隐藏起来。

## 1.6 能力边界的正确问法

与其问“这个模型聪明吗”，不如问：

1. 在什么输入分布上测过？是否见过类似数据？
2. 错误的代价是轻微改写，还是医疗、财务和安全事故？
3. 能否引用来源、调用工具或请求人工确认？
4. 延迟、价格、隐私和可用性是否满足真实流程？

⭐ 这四个问题把“模型能力”改写成“系统能力”。一个小模型加高质量检索，可能胜过没有资料的大模型；一个高分基准模型，也可能不适合你的中文合同或内部流程。

## 1.7 一次 AI 项目怎样从失败开始

假设团队要做“自动审核报销单”。第一版把 OCR 文字直接送进分类器，结果在模糊照片、少数供应商和新格式上频繁误判。复盘时可以沿五个来源定位：

| 观察 | 可能原因 | 改进方向 |
|---|---|---|
| 小字识别错 | 表示丢失空间布局 | 版面分析、局部裁剪、多模态模型 |
| 新供应商误判 | 训练分布太窄 | 增加覆盖、检索最新规则、拒答 |
| “合理”但不合规 | 目标只奖励通过率 | 把合规约束加入指标和校验 |
| 速度太慢 | 模型或上下文过大 | 分层模型、缓存、异步队列 |
| 无人能解释 | 只保留最终标签 | 保存证据、规则命中和版本日志 |

这个案例说明：AI 并不是一个可随意替换的黑盒零件。数据和表示决定它看见什么，目标决定它偏向什么，流程决定错误是否会伤人。

## 🧪 动手实验：给日常软件画边界

挑选输入法、相册搜索、地图导航和垃圾邮件过滤器。对每个系统写出输入、输出、训练数据的可能来源、一个成功例子和一个失败例子，再标记它更接近规则、ML、DL 还是 GenAI。最后回答：如果把系统接入自动执行，哪一类错误必须先加人工确认？
