# 第一章 人工智能概述：先把“智能”说清楚

## 本章地图

很多争论从一句模糊的话开始：“这台机器有智能。”本章把这句话拆成可观察的任务、环境、目标和反馈，介绍符号主义、连接主义、行为主义三种传统，再用两次 AI 寒冬解释为什么承诺会周期性膨胀。最后建立 `AI ⊃ ML ⊃ DL ⊃ GenAI ⊃ LLM` 的概念层级，并给出判断一项技术是否真的有用的检查表。

## 1.1 用任务定义智能

把智能定义为“像人一样思考”会立即遇到测量困难：人类自己也会犯错，机器的内部过程又未必像人的大脑。工程上更实用的定义是：**系统在某个环境中，根据观察选择行动，并在明确目标上表现出适应性**。

这一定义包含四个要素：

| 要素 | 例子（送餐机器人） |
|---|---|
| 环境 | 楼道、房间、行人和电梯 |
| 观察 | 摄像头、地图、碰撞传感器 |
| 行动 | 规划路线、减速、呼叫电梯 |
| 目标 | 准时送达且不撞人、能耗可接受 |

换一个目标，所谓“智能”就会改变。只追求速度的机器人可能闯红灯，只追求满意度的客服可能答应不该答应的要求。因此讨论 AI 时先问“对谁、在何种环境、以什么代价完成什么任务”。

图灵测试把问题转换为语言行为：如果评审无法分辨对方是人还是机器，就称其通过测试。它提醒我们行为很重要，却不测事实准确、身体操作、长期记忆或意识。一个善于模仿的系统可以通过对话，仍然不适合替人做医疗决定。

💡 **类比**：考试高分说明学生熟悉这张试卷的题型，不等于他能在陌生工地安全操作。AI 评测也需要从“会答题”走向“在真实约束下完成任务”。

## 1.2 三个层次：能力、机制、体验

“模型会下棋”是能力陈述；“模型用搜索树”是机制陈述；“模型享受胜利”是体验陈述。今天的 AI 研究能可靠测量第一层，部分分析第二层，无法从语言输出证明第三层。

ANI（狭义 AI）在限定任务上工作，AGI（通用 AI）强调跨领域迁移和自主学习，ASI（超级智能）是超过人类整体能力的假设。它们不是按照参数量划线，也不是按照产品名称划线。聊天模型可能拥有很宽的 ANI 能力，但“宽”仍不等于通用。

⚠️ 拟人化语言很方便，却会隐藏边界。说“模型记得”时，可能只是上下文里有一段文字；说“模型想要”时，可能只是优化器产生了某种行为。写报告时把可观察的机制和主观体验分开。

## 1.3 三大学派的不同赌注

### 符号主义：智能是可组合的规则

符号系统用对象、关系和逻辑表达知识，通过搜索或推理得到结论。它适合规则稳定、需要审计的任务，例如税率计算和棋盘游戏。优点是中间步骤可检查，缺点是常识难以穷举，规则冲突和组合爆炸会迅速增加。

### 连接主义：智能是参数化的表示

神经网络把许多简单单元连接起来，从数据中调整权重。它能从像素、语音和文本学习层级特征，不必把每条规则写出来。代价是数据和算力需求高，错误原因不容易用一条规则概括，训练数据的偏差会进入模型。

### 行为主义与智能体：智能是环境中的适应

强化学习把系统放进环境，根据奖励改进策略。它适合连续决策和控制，但奖励写错会产生投机行为，模拟环境中有效的策略也可能在现实失效。

⭐ 三派不是“前者已死、后者完胜”的历史接力，而是三种归纳偏置。现代系统常让神经网络做感知，用符号规则做约束，再用强化学习优化行动。

## 1.4 两次寒冬告诉我们的事

1950~60 年代的早期系统在定理证明、棋类和玩具世界中表现亮眼。研究者高估了把常识形式化的速度，也低估了搜索空间、内存和计算时间。资金和兴趣下降，形成第一次寒冬。

1980 年代专家系统重新升温。它们把专家经验写成规则，在企业场景有效，但知识录入和维护成本极高；换一个领域就要重新编写。硬件市场和投资冷却后，第二次寒冬到来。

两次寒冬的共同结构是：演示被外推成普遍能力，承诺超过了数据、算力或维护预算。复苏并非单纯更聪明的算法，而是统计学习、互联网数据、GPU、开源软件和更好的评测同时成熟。

2012 年深度学习在图像任务上突破，2017 年 Transformer 让序列训练更易并行，随后大规模预训练把语言模型推向基础设施。这些节点都体现了“表示 + 规模 + 工程”的合力。

## 1.5 概念层级：五层伞面

```
AI  人工智能：让机器完成需要智能的任务
└─ ML  机器学习：从数据调整参数，而非只靠人写规则
   └─ DL  深度学习：用多层神经网络学习表示
      └─ GenAI  生成式 AI：生成新的文本、图像、音频或代码
         └─ LLM  大语言模型：以语言 token 为主要输入输出的基础模型
```

这是包含关系，不是质量排序。A* 寻路可以是 AI 但不是 ML；决策树是 ML 但不一定是 DL；扩散模型是 GenAI 但不是 LLM；一个 LLM 产品还可能包含检索、规则和工具。

判断时可以问：参数由谁给出？特征由谁形成？系统输出标签还是样本？主要处理哪种模态？答案比产品宣传中的“智能”更可靠。

## 1.6 AI 项目需要的五种资源

数据提供可学习的例子；目标函数规定什么算成功；结构决定信息如何流动；算力决定能否把参数调到位；人类流程决定错误是否被发现和纠正。缺任何一项，模型分数都可能与实际价值脱节。

以自动审核发票为例，OCR 误读金额属于表示问题，训练集没有新供应商属于数据问题，把“通过率”当唯一目标属于目标问题，响应太慢属于算力或架构问题，错误无人复核则属于流程问题。把失败归因到正确层级，修复才不会靠猜。

## 1.7 读懂 AI 新闻的四步法

1. 找主语：是一个模型、一个产品，还是一个包含人工流程的系统？
2. 找任务：在什么数据和环境中测量？是演示、基准还是线上结果？
3. 找规模：增加的是参数、数据、上下文、推理时间还是工具权限？
4. 找代价：延迟、价格、隐私、偏见和错误责任由谁承担？

## 1.8 三个容易混淆的“智能”

**自动化**是把已知步骤交给机器执行，例如按规则汇总表格；**适应性**是系统从数据或反馈改变行为，例如推荐器根据点击更新排序；**自主性**是系统在较少逐步指令下选择目标路径，例如 Agent 自己决定查哪些资料。三者可以分别存在：一个自动化脚本没有学习能力，一个推荐器有适应性却不能自主行动，一个自主 Agent 也可能只是调用固定工具。

谈“更智能”时要说清是哪一个维度。提高自主性通常会增加不可预测和权限风险，提高适应性则需要更多数据和监控；把自动化步骤做快，并不意味着系统获得了理解。

### 从研究演示到产品承诺

研究演示往往选择容易成功的样本，产品面对长尾输入、隐私限制、成本上限和持续维护。评估一项成果时，至少把论文中的任务、数据、基线、失败率和部署条件记下来。少一个条件，结论就可能被过度外推。

这也是“AI 效应”反复出现的原因：一旦某项能力变得稳定，人们就把它重新称作普通软件，不再觉得它是智能。名称会变化，任务的假设和错误代价不会；分析时应回到可观察的行为。

## 🧪 动手实验：给软件贴标签

选输入法、地图导航、相册搜索和聊天助手。为每个系统写出环境、观察、行动、目标，判断它更接近规则、ML、DL 或 GenAI，再写一个“看起来成功但其实失败”的例子。最后说明如果把它接入自动执行，哪一步需要人工确认。
