# 第六章 多模态大模型与具身智能：让预测接上世界

## 本章地图

文本模型只接收符号，现实任务却同时需要看、听、触摸和移动。本章从“多模态到底共享了什么”开始，拆解视觉语言模型（VLM）的编码器与接口，再讲视频、语音和跨模态生成。后半进入具身智能：VLA 如何输出动作，世界模型如何在脑中模拟未来，Sim2Real 为什么困难，机器人数据为何稀缺。核心不是堆模态，而是建立可反馈的行动闭环。

## 6.1 多模态的真正难点：对齐

把图片和文字放进同一个请求，并不等于模型理解它们的关系。系统需要知道哪个视觉区域对应哪个词，事件发生在何时，声音和画面是否描述同一件事，动作会怎样改变下一帧。

不同模态的采样率和噪声也不同：图像是一帧帧像素，语音是连续波形，触觉只在接触时出现。对齐可以发生在输入级、特征级或输出级，选择会影响延迟、信息损失和训练数据需求。

💡 **类比**：设计师的草图、工程师的尺寸和客户的口述只有共享编号和时间轴后才是一个项目。文件越多，接口越重要。

## 6.2 VLM 的基本拼装

一个常见 VLM 可以写成：

```
图像/视频 → 视觉编码器 → 视觉特征 → 模态接口
文本 token ──────────────────────────────┐
                                         ↓
                              语言模型 → 回答/工具调用
```

### 视觉编码器

ViT 或 CNN 把图像划成 patch 特征。视频还需要时间维度，可以抽帧、使用时空注意力或视频专用编码器。编码器的分辨率决定能否读小字，帧数决定能否捕捉动作。

### 模态接口

线性投影直接把视觉向量变到语言模型维度，简单但可能保留太多 token；查询压缩模块用少量可学习 query 从视觉特征中提炼信息，节省上下文；原生多模态模型则从训练初期就让不同模态共享部分表示。

⭐ 判断一个 VLM 的关键不是“用了哪个视觉模型”，而是问：视觉信息以多少 token、什么坐标、带不带位置和时间进入语言主干？

## 6.3 一次图像问答的隐藏步骤

客户端先读取和压缩图片，服务端可能裁剪、缩放或切成多个视图；编码器生成视觉特征；接口把特征转为模型可消费的向量；文本和视觉 token 拼成上下文；语言模型逐 token 生成；最后进行格式解析、引用、内容安全和人工升级。任何一步都可能造成错误。

如果图片过曝，模型不是“推理错”，而是观察缺失；如果小字在裁剪时消失，语言主干再强也无法恢复。产品应允许模型报告看不清、请求重拍，而不是逼它填空。

## 6.4 多模态输出与时间

文生图、文生音频和文生视频都需要生成一个连续结构。视频比单帧更难，因为身份、运动、光照和因果必须跨帧一致。抽帧太少会漏掉关键动作，逐帧高分辨率处理又昂贵，常见做法是全局低频扫描加局部高频重看。

实时语音还要处理端点检测、流式解码、打断和回声消除。延迟不是一个总数：首字延迟、每秒输出速度和用户打断后的恢复时间都会影响体验。

## 6.5 具身智能的任务定义

具身系统有传感器、身体和行动后果。它的目标不只是生成一句话，而是让环境状态朝目标移动：

$$s_{t+1}\sim p(s_{t+1}\mid s_t,a_t),\qquad a_t=\pi(o_{\le t},l,s_t)$$

`s` 是状态，`o` 是观察，`l` 是语言目标，`a` 是动作。动作可能是关节角、末端位姿或“抓取/放置”等技能。由于观察不完整，策略必须不断反馈，而不能只生成一次长计划。

### VLA：视觉、语言、动作统一

VLA 把图像 patch、语言 token 和机器人状态送入策略网络，输出一段动作。语言提供“做什么”，视觉提供“在哪里”，控制器保证“怎么稳定地做”。低层控制常保留传统 PID、轨迹规划或碰撞约束，高层模型不应直接拥有无限执行权。

## 6.6 世界模型：在内部试错

世界模型学习动作与状态转移，规划器可在内部滚动多个未来，选择成功概率较高的动作。这像在脑中排练“先拿起杯子再倒水”，能减少真实试错。

但预测误差会累积，柔软物体、陌生工具和人类反应很难准确模拟。世界模型适合提出候选和发现明显危险，不应替代真实传感器和安全控制器。

## 6.7 Sim2Real：仿真与现实的缝隙

仿真器能高速生成轨迹，却会在摩擦、质量、光照、延迟和传感器噪声上与现实不一致。域随机化在训练中随机改变这些因素，让策略不要依赖单一外观；系统辨识用真实数据估计物理参数；少量真实示范用于最后校准。

这是一场先验与数据的拔河：把重力和关节限制写进控制器，样本效率高但迁移受限；完全端到端学习灵活但数据和安全成本高。分层系统通常更容易诊断和接管。

⚠️ **易错误解**：VLM 能回答“杯子在桌上”不等于它拥有精确深度，也不等于它能抓稳杯子。感知置信度、空间坐标、动作可行性和执行反馈是四个不同环节，必须分别测量。

## 6.8 机器人数据为什么稀缺

互联网有海量文本和图片，却很少有“第一视角、带动作、带结果”的可靠轨迹。采集一条机器人示范需要设备、场地、操作者和安全监督，失败还可能损坏硬件。遥操作、模仿学习、视频自监督和仿真合成各有缺口，数据闭环往往比模型参数更成为壁垒。

## 6.9 行动系统的安全边界

动作白名单、速度与力限制、碰撞检测、急停、权限分级和人工接管应由独立控制层执行。高风险动作前要验证对象、位置、当前状态和用户授权；工具返回的文字只能是证据，不应自动升级为命令。所有动作都应可追踪、可暂停、尽量可回滚。

## 6.10 评测阶梯

先在离线数据测动作预测，再在仿真测成功率和碰撞率，随后做封闭场地真实测试，最后才进入开放环境。除了成功率，还应记录恢复时间、人工介入次数、能耗、磨损和对不同人群的安全差异。平均成功率掩盖不了“每十次就需人拉回一次”的事实。

### 感知冲突与缺失模态

真实环境可能没有声音、摄像头过曝，或视觉与触觉给出矛盾信号。系统应标记缺失、降低置信度并请求补充观察，而不是用语言把空白补成事实。传感器融合可以采用置信度加权、卡尔曼滤波或规则约束，但最终的安全控制器应拥有否决权。

具身智能还要面对人的动态行为。行人会改变路线，儿童不会遵守预设轨迹，家中物体的摆放也会持续变化。把人当作静态障碍物会产生危险策略，评测必须包含互动、打断和紧急停止。

## 6.11 从感知到行动的接口契约

一个稳妥的接口应明确四类字段：观察内容及时间戳、空间坐标与置信度、允许的动作范围、动作后的预期反馈。语言模型只能在契约允许的范围内提出技能；控制器检查碰撞、速度和状态后才执行。执行结果再回到观察队列，任何超时或矛盾都触发暂停。

这个契约也方便替换模型。更换视觉编码器不会悄悄改变关节限制，更换语言模型不会绕过急停。把安全约束写在模型外，是承认表示和预测永远不完整的工程选择。

## 🧪 动手实验：让 VLM 先举证再回答

选一张桌面照片，让模型先输出“物体、位置、证据区域、不确定性”表格，再回答计数或空间关系问题。遮挡一个物体后重问，比较它是否会降低置信度。若再接一个只读工具，观察视觉错误如何沿 Agent Loop 传到行动建议。
