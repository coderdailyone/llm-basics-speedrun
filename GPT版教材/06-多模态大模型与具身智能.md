# 第六章 多模态大模型与具身智能

## 本章地图

语言模型的世界只有 token，而现实世界同时有像素、声音、深度、触觉和动作。本章先区分“多模态输入”和“多模态输出”，再拆解 VLM 的视觉编码器、接口和语言主干；随后把输出从文字推进到动作，介绍 VLA、世界模型与 Sim2Real。主线是一个闭环：**感知 → 表示对齐 → 预测 → 行动 → 反馈**。

## 6.1 为什么多模态不是“加一个图片参数”

同一句“把杯子放到左边”，如果没有视觉，模型不知道杯子在哪里；如果没有动作接口，它也无法真的移动杯子。文本擅长抽象和指令，视觉提供空间，声音提供时间与语气，触觉提供接触状态。多模态系统的难点是让这些信号在同一个任务坐标系中互相约束。

💡 **类比**：一个项目组里，设计师给草图，工程师给尺寸，客户给口头需求。把三份文件丢进共享文件夹不等于协作，必须有统一的编号、时间轴和责任接口。

## 6.2 VLM 的三段式架构

最常见的视觉语言模型（VLM）由三部分组成：

```
图像/视频 → 视觉编码器 → 视觉特征
                         ↓ 投影/查询接口
文本 token ───────────→ 语言模型 → 文本回答
```

### 视觉编码器

CNN 或 ViT 把图像变成 patch 特征。视频还要处理时间维，可以抽帧、使用 3D 卷积或时空注意力。编码器决定模型能看多细、多少帧以及对空间关系的敏感度。

### 模态接口

最简单的做法是线性投影，把视觉特征映射到语言模型的 embedding 维度，再当作“视觉 token”拼进上下文。查询变换器（Q-Former）用少量可学习查询从大量视觉 patch 中提炼摘要，节省上下文。更深的路线是从训练一开始就共享离散或连续表示，让模型原生处理图文音频。

⭐ 接口是系统的瓶颈：投影太弱会丢空间细节，视觉 token 太多会挤占上下文，冻结语言模型又限制跨模态对齐。看论文时不要只记编码器名字，要问“视觉信息以什么格式进入主干”。

### 语言主干与解码

语言模型根据文本和视觉 token 生成答案。它可以做描述、问答、OCR、图表分析或视觉定位，但生成式输出仍可能“看见不存在的东西”。让模型说出“我看不清”需要训练数据和运行时策略共同支持。

## 6.3 一次多模态调用的完整流程

1. 客户端读取图片，统一尺寸、色彩和压缩格式；
2. 视觉编码器生成特征，必要时进行裁剪或多尺度处理；
3. 接口模块把特征映射为语言模型可接受的向量序列；
4. 文本提示、视觉 token 和对话历史拼成上下文；
5. 语言模型自回归生成回答或工具调用；
6. 后处理做结构化解析、引用、内容安全和人工升级。

⚠️ 图像“上传成功”不代表模型使用了全部像素。分辨率、裁剪、压缩、token 上限和注意力分配都会影响细节；评测必须包含小字、遮挡、反光和多图关系。

## 6.4 多模态输出：从内容到时间轴

文本到图像通常由扩散模型或自回归图像模型完成；文本到语音需要声学模型和声码器；视频生成还要维持跨帧身份、物理和镜头连续性。输出模态越丰富，越需要记录来源和编辑历史，因为真假判断会变得困难。

图像、音频和视频也可以反向成为工具：模型读仪表盘、听会议、看生产线，再决定是否调用数据库或发出告警。这里的关键不是“模态越多越好”，而是每种模态是否减少了任务中的不确定性。

## 6.5 具身智能：让预测连接到世界

具身智能系统有身体、传感器和动作空间。它面对的不是“回答是否通顺”，而是“抓取是否成功、是否撞到人、五分钟后物体在哪里”。Moravec 悖论指出，高层棋类和语言对计算机相对容易，低层感知和灵巧操作却很难，因为后者需要大量隐性身体经验。

### VLA：视觉—语言—动作

VLA 模型把图像、语言指令和机器人状态映射为动作序列：

$$a_{t:t+k}=\pi(o_{\le t},\,l,\,s_t)$$

其中 `o` 是观察，`l` 是语言，`s` 是状态，`a` 是未来一段动作。动作可以是关节角、末端位姿或离散技能。语言提供目标，视觉提供场景，控制器负责执行与反馈。

### 世界模型：先在脑中试错

世界模型学习状态如何随动作变化：`s_{t+1}≈f(s_t,a_t)`。规划器可以在模型内部滚动多个未来，再选择风险较小的动作，减少真实机器人试错。问题是模型预测会累积误差，长时间想象不等于真实物理规律。

## 6.6 Sim2Real 与数据瓶颈

仿真器能高速生成轨迹，却和现实存在摩擦、光照、传感器噪声、物体柔软度等差异。域随机化在训练时随机改变材质、质量和摄像机，让策略学到更稳健的规律；系统辨识则用真实数据校准仿真参数；少量真实示范用于最后对齐。

机器人数据比文本稀缺得多：每条轨迹需要设备、场地、时间和安全监督，失败还可能损坏硬件。遥操作、模仿学习、自监督视频和仿真合成各有成本，未来竞争很大一部分是数据闭环而非模型结构。

## 6.7 安全的行动闭环

行动系统必须有可观测状态、动作白名单、速度与力限制、碰撞检测、紧急停止和人工接管。模型输出“打开阀门”前，系统应验证对象、权限、当前状态和操作后果。把自然语言直接映射到执行器，是把不确定性放大到现实世界。

## 6.8 语音与时间结构

语音不是“带声音的文字”。波形先经过声学编码得到时间序列，语音识别把它转成 token，语言模型进行理解，语音合成再把文字变回声学特征和波形。实时对话需要流式分块、端点检测和打断机制，任何一环延迟过大都会破坏交互。

视频还包含动作速度和因果顺序。抽帧太稀会漏掉关键事件，逐帧处理又昂贵；常用策略是低帧率全局扫描加高帧率局部重看。评测不能只问“视频里有什么”，还要问“先发生什么、谁导致了什么、当前状态是否仍然成立”。

### 模态缺失与冲突

真实环境经常没有声音、摄像头过曝或传感器互相矛盾。模型应能标出缺失模态并降低置信度，而不是用语言把空白补成事实。传感器融合可用置信度加权、卡尔曼滤波或规则约束，但最终仍需安全控制器验证。

## 6.9 具身系统的评测阶梯

先在离线轨迹上测动作预测，再在仿真中测成功率与碰撞率，之后做受限真实测试，最后才进入开放场景。每一级都记录任务成功、恢复时间、能耗、磨损和人工介入次数。平均成功率 90% 的机器人，如果每十次就需要人拉回一次，可能并不适合家庭环境。

### 具身先验与数据效率

机器人可以把物体尺寸、关节限制和重力写进控制器，也可以让模型从演示中学习。硬编码的物理约束提升安全和样本效率，却降低了对新硬件的迁移性；完全端到端学习更灵活，却需要大量覆盖不同失败模式的数据。实际系统往往采用分层方案：高层模型提出技能，低层控制器保证稳定，安全模块拥有最终否决权。

这也解释了“先验与数据的拔河”：在开放世界中，人类先验仍然是昂贵但有效的压缩。把先验写成可替换模块，比把所有假设埋在一个巨大网络里更便于诊断。

## 🧪 动手实验：给 VLM 加一层证据表

选一张桌面照片，让模型先输出“看见的物体—位置—证据区域”表格，再回答一个计数或空间关系问题。遮挡关键区域后重问，要求模型标出不确定项。比较直接回答与证据约束回答的错误类型，体会接口设计如何影响可靠性。
