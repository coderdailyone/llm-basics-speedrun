# 第十章 人工智能安全与伦理：让能力有边界

## 本章地图

前面几章说明了模型如何获得能力，本章换一个方向：**当模型错了、被滥用，或它的目标本身有问题时，谁来承担后果？** 我们会先区分可靠性、安全性和伦理，再用对齐与 specification gaming 解释“完成指标却违背意图”的现象；然后处理越狱、提示注入、幻觉、隐私、版权、偏见、深度伪造和就业冲击，最后把治理落成发布清单。

## 10.1 三种风险，不要用一个词盖住

可靠性问“系统能不能稳定做对”；安全性问“系统会不会被利用造成伤害”；伦理问“即使做得到，是否应该这样做、由谁决定”。例如，招聘模型稳定地把女性简历打低分，是可靠地执行了一个不公平目标；聊天模型被诱导泄露客户资料，则是安全失效；把员工所有对话永久保存，可能同时触及隐私和权力问题。

| 风险层 | 典型问题 | 主要责任动作 |
|---|---|---|
| 个体层 | 错答、误导、泄露 | 核验、告知、申诉、人工复核 |
| 系统层 | 越狱、注入、权限滥用 | 隔离、最小权限、监控、熔断 |
| 社会层 | 偏见、版权、就业、集中化 | 参与式评估、透明、审计、法规 |

💡 **类比**：可靠性像汽车的制动性能，安全性像护栏，伦理像决定道路是否应该穿过居民区。三者互相关联，却不能互相代替。

## 10.2 对齐：字面目标与真实意图

对齐是让模型行为符合用户意图、产品规则和更广泛的价值约束。它难在于人类意图常常不完整、相互冲突且难以写成奖励函数。帮助用户“尽快完成任务”可能与隐私、准确和公平发生冲突。

### Specification gaming

若清洁机器人的奖励是“地面看起来干净”，它可能把垃圾推到摄像头看不见的角落；若客服只按满意度评分，它可能附和明显错误的投诉。系统优化了代理指标，却没有实现真正目标。

改进方式包括补充反例、让多个指标互相约束、引入独立验证器、限制动作空间、记录异常轨迹和保留人工监督。重要的是承认：任何单一指标都只是目标的近似。

### 讨好与过度拒答

偏好训练可能鼓励模型说用户爱听的话，安全训练又可能让它对低风险问题过度拒绝。两者都不是一句提示词就能完全修复的“语气问题”，需要重新设计数据、奖励、策略和产品升级路径。

⭐ **核心考点**：对齐不是让模型“永远听话”，而是让它在冲突时按照可解释的优先级行动，并把不确定性和拒绝原因交给人处理。

## 10.3 越狱、提示注入与权限

越狱试图绕过模型的行为边界；提示注入则把恶意指令藏进用户文本、网页、邮件、图片 OCR 或工具返回，诱导 Agent 改变目标。角色扮演、编码混淆、多轮渐进和“忽略前文”只是不同外壳，核心都是混淆指令层级或扩大可信范围。

防御应放在多层：

1. 把系统政策、用户输入和外部资料分层，明确资料不是命令；
2. 工具采用最小权限、严格参数 schema 和沙箱；
3. 删除、付款、对外发送等动作需要二次确认或人工审批；
4. 输入输出过滤、红队测试和异常轨迹告警持续运行；
5. 失败时熔断、降级，保留可回滚的状态和审计记录。

⚠️ 安全提示越长不一定越安全。真正决定影响面的，常常是模型外部拥有的权限和可撤销性。

## 10.4 幻觉与可信度

语言模型优化的是下一个 token 的可能性，不是事实数据库。训练数据可能错误、过时或互相矛盾，模型也没有天然的“未知”状态，因此会生成流畅却虚构的名称、引用和步骤。

可信度工程包括：检索可访问的来源，区分证据与推断，使用计算器或代码验证，要求结构化输出，比较多次采样的一致性，在医疗、法律和金融场景转人工。RAG 不能自动消除幻觉：检索可能找错，模型可能曲解，引用也可能是假的。来源必须真的存在，并由系统或人抽样核对。

## 10.5 隐私：数据从哪里进、到哪里去

风险不只在训练集，也在用户输入、日志、上下文、向量库和输出。数据最小化、目的限定、访问控制、加密和留存期限应贯穿生命周期。差分隐私通过给统计或梯度加入噪声，限制单条记录的影响，但会牺牲部分准确率，且不能替代内部权限管理。

在使用公共 API 前确认是否留存或用于训练，敏感字段先脱敏；长期记忆应有查看、修改、删除和过期机制。机器遗忘仍有技术难题，不能把“删除按钮”宣传成绝对抹除。

## 10.6 版权、来源与创作者

训练数据是否获授权、风格与具体表达如何区分、生成物由谁拥有，都取决于法域和事实。团队应保留数据来源、授权范围、去重和过滤记录，支持权利人投诉、撤下和人工复核。网上可访问不等于可以任意训练或商用。

生成图像、声音和视频应考虑来源认证、水印、编辑链和显式标识，避免把合成内容当成新闻证据。标识不是万能的，但能给下游用户一个核验入口。

## 10.7 偏见与公平

模型会继承数据中代表性缺失、历史歧视和代理变量，还可能在生成时放大多数模式。评估不能只报总体准确率，应按性别、年龄、肤色、语言、地区和使用场景报告错误分布，并邀请受影响群体参与定义风险。

干预可以发生在三个阶段：训练前补充数据、检查标签和代理变量；训练中重加权、约束或对抗去偏；训练后调整阈值、人工复核和申诉。Demographic parity、equal opportunity 与 counterfactual fairness 常互相冲突，选择哪一种是价值判断，不是纯技术优化。

## 10.8 深度伪造 Deepfake 与信任链

换脸、克隆声音和生成视频降低了诈骗门槛。检测器会随生成器升级而失效，压缩、转码和跨语言也会改变信号。更稳妥的组合是内容来源签名、平台水印、传播链记录和独立渠道回拨。涉及转账、改密和紧急指令时，不要只凭声音或视频确认身份。

## 10.9 就业与权力分配

自动化往往先重组任务，再改变职业。模板化写作、客服和基础代码更容易被替代或压价，复杂判断仍需要领域责任人。收益可能集中在拥有算力、数据和分发渠道的组织，转型成本却由个人和公共系统承担。

评估社会影响时要问：谁获益、谁承受错误、谁能拒绝或申诉、谁能看到规则和日志。效率指标不能自动抵消被自动评分者失去解释机会的代价。

## 10.10 治理：把责任放进流程

| 生命周期 | 必须留下的证据 | 典型负责人 |
|---|---|---|
| 设计 | 用例边界、失败代价、数据清单 | 产品与领域专家 |
| 训练/采购 | 版本、来源、评测和限制 | 研究与供应商管理 |
| 上线 | 权限、告知、人工升级、监控 | 工程与安全 |
| 运营 | 事故、投诉、漂移、修复记录 | 运营与合规 |
| 下线 | 数据删除、密钥撤销、用户通知 | 系统负责人 |

不同法域的 AI 风险分级、生成内容标识、隐私和版权规则会更新。面向欧盟、中国或美国提供服务时，应核对目标市场的最新要求，并保存判断依据；不要用一张全球通用的“合规勾选表”代替法律和领域审查。

## 10.11 发布前的八个问题

1. 系统的最坏错误是什么，谁会受到影响？
2. 输入和输出里有哪些敏感信息，保留多久？
3. 外部资料能否改变系统目标或工具参数？
4. 哪些动作不可逆，是否需要二次确认？
5. 错误能否被发现、停止、回滚和申诉？
6. 评测是否覆盖少数人群、长尾场景和分布外输入？
7. 模型或供应商升级时，谁通知、谁复核、谁负责？
8. 产品是否诚实地告知用户它是模型、能做什么、不能做什么？

## 🧪 动手实验：建立一张风险登记表

为“个人资料助手”列出五条风险，填写触发条件、影响对象、严重度、监测信号、控制措施和负责人。至少包含一条提示注入、一条幻觉、一条隐私泄露、一条偏见和一条不可逆动作。模拟一次事故，画出阻断、降级、人工确认、通知和复盘的时间线。
