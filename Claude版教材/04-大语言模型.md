## 4.1 大语言模型是什么

**一句话定义**：大语言模型（Large Language Model, LLM）是**用海量文本训练的、以 Transformer 为架构的超大规模自回归语言模型**——它做的事情自始至终只有一件：**给定前文，预测下一个 token 的概率分布**。

三个"大"：
- **参数大**：数十亿（B）到数万亿（T）级参数。7B、70B、405B 这些型号数字指的就是参数量。
- **数据大**：训练语料数万亿 token，大致相当于把互联网公开文本的精华读了一遍。
- **算力大**：前沿模型训练需要上万块 GPU 运行数月，成本以亿美元计。

**先解决一个哲学疑惑**：只是"预测下一个词"，怎么会产生翻译、写代码、做数学题的能力？

关键在于：**把下一个词预测到极致，是一个深不见底的任务**。预测"3 + 5 = __"需要会算术；预测"《哈姆雷特》的作者是__"需要知识；预测一段侦探小说里"凶手是__"需要推理整个情节；预测对话中人物的下一句话需要建模其心理。**训练目标简单，不代表达成目标所需的能力简单**。为了在海量、多样的文本上都预测得准，模型被迫在内部构建起语法、事实、逻辑乃至朴素世界模型的表示。这个视角叫"**压缩即智能**"：好的预测器等价于好的压缩器，而对世界的深刻理解是极致压缩的前提。

当然,"它究竟是真理解还是高级模式匹配"仍有争论（第 7 章讨论）,但工程事实是明确的:能力确实出现了。

## 4.2 解剖 Transformer：LLM 的引擎

第 2 章讲了注意力的直觉，这里把 GPT 式模型（decoder-only Transformer）的完整结构串一遍。

### 4.2.1 整体流水线

一个 token 从进入模型到产出预测，经历：

```
文本 "今天天气真"
  │ ① Tokenizer 分词
  ▼
token 序列 [今天, 天气, 真]  → 各自的整数 ID
  │ ② Embedding 查表
  ▼
每个 token → 一个 d 维向量（d=数千,称为隐藏维度）+ 位置信息
  │ ③ N 层 Transformer 块（N=数十到上百层）
  ▼
┌─────────── 每层内部 ───────────┐
│  多头自注意力  ← token 之间交换信息 │
│  （+残差连接+LayerNorm）          │
│  前馈网络 FFN  ← 每个 token 独立加工│
│  （+残差连接+LayerNorm）          │
└────────────────────────────────┘
  │ ④ 输出层（把最后一个位置的向量映射回词表）
  ▼
词表上每个 token 的概率:  好:0.62  不错:0.21  冷:0.08 ...
  │ ⑤ 采样
  ▼
选出 "好" → 拼回输入 → 回到①继续预测下一个 → 循环直到结束
```

几个要点：

- **自回归生成**：模型一次只生成一个 token，生成后拼接到输入末尾再预测下一个。写一篇千字文 = 这个循环转数千圈。这就是你看到 ChatGPT"逐字打字"的原因——它真的是一个词一个词想出来的。
- **因果掩码（Causal Mask）**：训练和生成时，注意力只允许看左侧（前文），不许偷看未来——否则"预测下一个词"的训练就作弊了。
- **注意力层 vs FFN 层的分工**（直觉版）：注意力负责**token 之间搬运信息**（"它"去把"苹果店"的信息搬过来）；FFN 负责**对每个 token 独立做深加工**，且被认为是**存储知识**的主要场所（占了约 2/3 的参数量）。研究者已能在 FFN 权重中定位并修改具体事实（如"巴黎是法国首都"）。
- **多头注意力**：每层几十个"头"并行，各自负责不同关系。可解释性研究发现了分工明确的头：专盯上一个词的头、专做指代消解的头、专门复制重复模式的"归纳头（induction head）"等。

### 4.2.2 采样：概率怎么变成文字

模型输出的是概率分布，如何选词大有讲究：

- **贪心解码**：永远选概率最高的词。稳定但呆板，容易复读。
- **温度（Temperature）**：调节分布的"尖锐度"。T→0 趋近贪心（确定性强，适合数学/代码）；T 高则更随机（适合创意写作）。API 里的 temperature 参数就是它。
- **Top-p（核采样）**：只在累计概率前 p（如 90%）的候选里采样，砍掉长尾胡话。
- 重要认知：**同一个问题问两次答案不同，不是模型"心情"变了，而是采样的随机性**。

### 4.2.3 上下文窗口与 KV 缓存

- **上下文窗口（Context Window）**：模型一次能处理的最大 token 数——它的"工作记忆"容量。从 GPT-3 的 2K 一路涨到如今主流的 128K～1M+（数十万汉字）。超窗的内容模型完全看不见；早期"聊着聊着忘了开头"就是前文被截断了。
- **平方复杂度**：注意力要计算每对 token 之间的关联，计算量随长度平方增长——长上下文昂贵的根源。工程优化包括 FlashAttention（优化显存访问）、稀疏/滑窗注意力、以及推理时的 **KV 缓存**（把已算过的 Key/Value 存下来，生成新 token 时不重算前文——这也是"提示词缓存"计费更便宜的原理）。
- **大海捞针问题**：窗口长≠用得好。测试表明模型对超长上下文中部的信息利用率会下降（"lost in the middle"），新一代模型已大幅改善但未根除。

### 4.2.4 混合专家（MoE）：让大模型"稀疏"起来

参数越多能力越强，但推理成本也线性上涨。**混合专家（Mixture of Experts, MoE）**的思路：把 FFN 层复制成多份"专家"，每个 token 经过一个可学习的**路由器**，只激活其中少数几个专家：

```
                    ┌─ 专家1（数学向）
token → 路由器 ──选2个→ 专家2（代码向）   ← 只算被选中的
                    ├─ 专家3（多语言向）
                    └─ ... 共 8~256 个专家
```

效果：**总参数量巨大（知识容量大），每次实际计算量却只相当于小模型**。例如一个"总参数 700B、激活 40B"的 MoE 模型，推理成本接近 40B 稠密模型，能力却远超之。GPT-4 被广泛报道采用 MoE；Mixtral、DeepSeek-V3 等开源模型将其发扬光大。**当前几乎所有前沿大模型都是 MoE 架构**。（注意：专家的分工是训练中自发形成的，往往按 token 模式而非人类直觉的"学科"划分。）

## 4.3 Scaling Law：力大砖飞的科学

### 4.3.1 规模定律

2020 年 OpenAI 的 Kaplan 等人发现：语言模型的损失（预测误差）随**模型参数量 N、数据量 D、计算量 C** 的增加，呈现平滑的**幂律下降**——在对数坐标下是一条直线，横跨多个数量级都成立。

这条定律的震撼之处在于**可预测性**：训练大模型前，可以先用小模型的实验外推出大模型的性能，把一场数亿美元的豪赌变成有把握的工程。GPT-4 的技术报告明确说，其最终性能在训练前就被小规模实验准确预测。

**Chinchilla 修正（2022, DeepMind）**：给定算力预算，参数和数据要**均衡配置**——最优比例约为每个参数配 20 个 token 的数据。此前业界普遍"参数过大、数据太少"（GPT-3 就训练不充分）。此后风向转变，且实践中普遍"过训练"（如 8B 参数配 15T token，远超 20:1）——因为训练时多花算力换来小模型，**推理时便宜**，总账更划算。

### 4.3.2 涌现能力

更神奇的现象：某些能力在小模型上完全不存在，规模跨过某个阈值后**突然出现**——称为**涌现能力（Emergent Abilities）**。典型例子：多步算术、上下文学习、指令跟随、思维链推理。

（学界有争论：部分"涌现"可能是评测指标不连续造成的假象——用连续指标看，能力其实是渐进增长的。但工程上"小模型做不了、大模型能做"的分界真实存在。）

### 4.3.3 Scaling 的三个阶段

1. **预训练 Scaling**（2018–2023 主旋律）：更大模型+更多数据。目前遇到瓶颈：高质量文本数据接近枯竭。
2. **后训练 Scaling**：在对齐、合成数据、蒸馏上加大投入。
3. **推理时 Scaling（Test-time Scaling）**（2024 起的新前沿）：让模型在**回答时**花更多算力思考——生成长的思维链、自我检查、多路径搜索。o1/R1 类推理模型的原理（见 4.6 节）。

## 4.4 从预训练到产品：LLM 的完整生产线

一个"读遍互联网的下一词预测器"距离能用的助手还很远。完整流程三大阶段：

```
① 预训练         → 基座模型（Base Model）：博学但"不听话"
② 监督微调 SFT    → 指令模型雏形：学会对话格式与听指令
③ 偏好对齐 RLHF   → 助手模型（如 ChatGPT/Claude）：有用、诚实、无害
```

### 4.4.1 预训练：读遍互联网

- **数据**：网页抓取（Common Crawl 等）、书籍、论文、代码、百科、论坛。原始数据极脏，**数据清洗是核心竞争力**：去重、去广告垃圾、质量打分、毒性过滤、多语言配比、代码与数学的比例调配（研究表明代码数据能提升通用推理能力）。
- **训练**：数千到数万块 GPU，数据并行+张量并行+流水线并行切分模型，训练数月。期间要对抗硬件故障、损失尖峰等工程灾难。
- **产物——基座模型**的行为很有启发性：它只会"续写"。你问"中国的首都是哪里？"它可能续写出"这是小学地理常见考题……"而不是回答你——因为互联网上这句话后面往往真的跟着这种文字。**它是文本分布的模拟器，不是助手。**

### 4.4.2 监督微调（SFT）：学会对话

用数万到数百万条高质量的**"指令→理想回答"**样例继续训练：

```
指令：用通俗语言解释什么是黑洞
理想回答：黑洞是一种引力极强的天体……（人类专家撰写或精选）
```

模型由此学会：识别对话格式、按指令行事、以助手的口吻回应。SFT 数据量远小于预训练（万分之一都不到），但**质量决定了模型的"性格"底色**。这一步也称指令微调（Instruction Tuning）。

### 4.4.3 RLHF：向人类偏好对齐

SFT 后模型会对话了，但"好回答"的标准微妙（有用性、诚实性、无害性的平衡）很难用示例穷尽——比较容易，示范难：人类很难写出完美回答，但很容易判断两个回答哪个更好。**基于人类反馈的强化学习（RLHF）**利用这一点：

```
第一步：训练奖励模型（Reward Model）
  同一提示 → 模型生成多个回答 → 人类标注员排序（A>B>C）
  → 用排序数据训练一个"打分器"，学会预测人类偏好

第二步：强化学习优化
  语言模型生成回答 → 奖励模型打分 → 用 RL 算法（如 PPO）更新语言模型,
  最大化得分,同时约束不要偏离原模型太远（防止钻空子退化成胡话）
```

RLHF 是 ChatGPT 相对 GPT-3 体验飞跃的关键。相关变体与发展：

- **DPO（直接偏好优化）**：跳过奖励模型和 RL，直接用偏好数据做类似监督学习的优化——简单稳定，被广泛采用。
- **RLAIF / Constitutional AI**（Anthropic）：用 AI 依据一部"宪法"（原则清单）来生成反馈替代部分人类标注，提高规模与一致性。
- **代价——对齐税与谄媚**：对齐可能轻微损失某些能力（对齐税）；按"人类喜欢"优化会催生**谄媚（sycophancy）**——迎合用户的错误观点、顺着说好听的。这是当前对齐研究的活跃战场（第 10 章展开）。

### 4.4.4 上线之后：系统提示词与持续迭代

产品化的模型还套着一层**系统提示词（System Prompt）**——运营方写的隐藏指令（角色设定、行为边界、当前日期等）。你与 ChatGPT 的每轮对话，实际输入是"系统提示词+历史对话+你的新消息"的拼接。理解这一点就理解了许多"模型行为玄学"。

## 4.5 使用与增强：让 LLM 干活的技术栈

模型能力固定后，还有一整层"用法技术"决定实际效果：

### 4.5.1 提示工程（Prompt Engineering）

高频有效技巧及其原理：

| 技巧 | 做法 | 为什么有效 |
|---|---|---|
| 角色设定 | "你是一位资深税务律师" | 把输出分布拉向该角色的语料区域 |
| 少样本示例 | 给 2~5 个输入输出例子 | 上下文学习,现场归纳任务模式 |
| **思维链 (CoT)** | "请一步一步思考" | 见下 |
| 结构化约束 | "以 JSON 格式输出,字段为…" | 缩小输出空间,便于程序解析 |
| 拆解任务 | 把大任务拆成多轮小任务 | 每步都在模型能力舒适区内 |

**思维链（Chain-of-Thought, CoT）**值得单独理解：让模型在给答案前先写出推理步骤，数学/逻辑题正确率大幅提升。原理：自回归模型的每个 token 计算量是固定的，直接蹦答案等于"心算"；把中间步骤写出来，相当于**把计算展开到输出序列里，用生成的 token 作为草稿纸**——每一步都以前面的正确中间结果为条件，难题被分解。这个朴素技巧正是后来"推理模型"的思想源头。

### 4.5.2 检索增强生成（RAG）

模型的知识冻结在训练截止日，且私有资料它没见过。**RAG（Retrieval-Augmented Generation）**的解法：

```
用户提问 → 在知识库中检索相关文档（通常用向量相似度搜索）
        → 把检索到的段落塞进提示词 → 模型"看着资料"回答并引用
```

优点：知识可实时更新、可溯源、大幅减少幻觉、企业私有数据不用训进模型。RAG 是目前企业落地 LLM 的最主流架构。其核心组件**向量数据库**存储文本的嵌入向量（第 3 章词向量思想的直系后代——整段文本压成一个语义向量）。

### 4.5.3 微调与高效微调

需要深度定制（固定风格、专业领域、私有任务）时微调自己的模型。全参数微调太贵，主流用**参数高效微调（PEFT）**，代表是 **LoRA**：冻结原模型，只在各层旁挂两个小矩阵学习"增量"，可训练参数降到千分之几，单卡即可微调 7B 模型。变体 QLoRA 进一步把原模型量化到 4bit 省显存。

**选型决策树**（实践口诀）：先试提示工程 → 知识问题用 RAG → 行为/风格/格式问题才微调 → 三者常组合使用。

### 4.5.4 工具调用与智能体

让模型突破"只会生成文本"的边界：**函数调用（Function Calling）**——开发者声明可用工具（计算器、搜索、数据库、代码执行……），模型在需要时输出结构化的调用请求，外部系统执行后把结果回填，模型继续作答。这是弥补 LLM 算术差、知识旧、无法行动三大短板的通用方案，也是**智能体（Agent）**的技术地基——第 8 章专章展开。

## 4.6 推理模型：让模型学会"慢想"

2024 年起的重要范式演进：**推理模型（Reasoning Model）**，代表为 OpenAI o1/o3、DeepSeek-R1、Claude 与 Gemini 的扩展思考模式。

- **核心思想**：与其只在训练时堆算力，不如让模型**回答时**先生成一段很长的内部思维链（尝试、检查、发现错误、回退、换路），再给最终答案——**推理时扩展（test-time scaling）**：思考 token 越多，难题正确率越高。
- **怎么训出来的**：以 DeepSeek-R1 公开的方法为例——在**结果可自动验证**的任务（数学有标准答案、代码可跑测试）上做大规模强化学习：答对给奖励，模型为了拿奖励**自发学会**了反思、验算、纠错等行为，思维链越长越像人类的草稿。无需人工示范推理过程,推理行为是 RL 中涌现的。
- **效果**：数学竞赛、编程竞赛等硬推理任务的成绩从"业余"跃升到接近或超过人类顶尖选手水平；日常闲聊类任务则收益小、延迟与成本高。
- **认知框架**：可类比人类的"快思考/慢思考"双系统——普通模式是直觉应答（系统 1），推理模式是刻意推演（系统 2）。现代旗舰模型多做成**混合模式**：简单问题秒答,难题自动或按需深想。

## 4.7 评测与短板：清醒地认识 LLM

### 4.7.1 怎么衡量模型好坏

- **学术基准**：MMLU（多学科选择题）、GSM8K/MATH（数学）、HumanEval/SWE-bench（代码）、GPQA（研究生级科学题）等。问题：**基准污染**（测试题混进训练数据导致虚高）、刷榜过拟合、上限饱和。
- **人类偏好对战**：如 Chatbot Arena——匿名双模型对答,用户投票,算 Elo 等级分。更贴近真实体验,但偏向"讨喜"而非"正确"。
- **AI 当裁判（LLM-as-a-Judge）**：用强模型给其他模型打分,便宜可扩展,但有自偏袒等偏差。
- **实践建议**：不迷信任何单一榜单；**用自己的真实任务建立小规模私有评测集**,是选型的最可靠方法。

### 4.7.2 幻觉：最著名的短板

**幻觉（Hallucination）**：模型以流利、自信的口吻输出虚假内容——编造不存在的论文、法条、API、人物事迹。

**根源是机制性的**，不是"bug"：
1. 模型的本职是**生成概率上合理的文本**，"听起来对"与"事实上对"在训练目标里没有区分。
2. 知识以统计方式弥散存储，相近的名字/概念会串线（把 A 的事迹安到 B 头上）。
3. 训练与对齐都在鼓励"给出回答"——考试蒙题策略：不会也要写满,历史上"我不知道"很少被奖励。（新一代对齐目标已开始显式奖励承认不确定。）

**缓解手段**（无法根除）：RAG 给资料、要求引用来源、让模型自查、多次采样看一致性、推理模型验算、以及用户侧的**关键信息必须核实**。

**使用原则**：把 LLM 当**极其博学但偶尔一本正经胡说的顾问**——头脑风暴、写作、编程放心用（错了能看出来/能运行验证），引用它给的"事实、数字、文献"前必须核实（错了看不出来）。

### 4.7.3 其他重要局限

- **知识截止**：不知道训练日期之后的世界（靠搜索工具弥补）。
- **算术与精确操作**：token 化+概率生成天然不擅长长数字运算、字符级操作（靠调工具弥补）。
- **逆转诅咒**：学过"A 是 B 的母亲"不代表能答"B 的母亲是谁"——知识的存储是有方向性的。
- **提示词注入（Prompt Injection）**：恶意文本可诱导模型违背原指令,是 LLM 应用最主要的安全风险之一（第 10 章）。
- **自我认知不可靠**：模型对"你为什么这么答""你会不会做 X"的自述不可信——它并不能真正内省自己的权重。

## 4.8 生态格局速览

- **闭源前沿**：OpenAI（GPT 系）、Anthropic（Claude 系）、Google（Gemini 系）——通过 API/订阅提供,能力最前沿。
- **开源/开放权重**：Meta 的 Llama 系、DeepSeek（以极低成本训出前沿级模型并公开方法震动业界）、Qwen（通义千问）、Mistral 等——可私有化部署、可微调、可研究,是学术界与中小企业的主力。"开源追赶闭源"的差距在持续缩小。
- **小模型（SLM）**：数亿~几 B 参数,手机/端侧可跑,靠蒸馏（用大模型的输出教小模型）获得远超其体量的能力。
- **基础设施**：训练框架（PyTorch+Megatron/DeepSpeed）、推理引擎（vLLM、SGLang、llama.cpp）、量化技术（把权重压到 8/4bit,显存减半再减半,精度损失很小）。

## 4.9 本章小结

1. LLM = 超大规模 Transformer 自回归语言模型；**唯一动作是预测下一个 token**,但"压缩即智能"——预测到极致必须内化知识与推理。
2. 生成是逐 token 循环；**温度/Top-p 采样**造成同题不同答；**上下文窗口**是工作记忆,注意力平方复杂度是其代价；**MoE** 用稀疏激活实现"参数大、计算省",已成前沿标配。
3. **Scaling Law**：损失随参数/数据/算力幂律下降且可预测;Chinchilla 给出配比;**涌现能力**在规模阈值后出现;前沿已从预训练 Scaling 转向**推理时 Scaling**。
4. 生产线三部曲：**预训练**（基座模型,只会续写）→ **SFT**（学会听指令）→ **RLHF/DPO**（对齐人类偏好,代价是对齐税与谄媚倾向）。产品层再叠加系统提示词。
5. 用法技术栈:**提示工程**（CoT=把计算展开成 token 草稿纸）→ **RAG**（外挂可更新知识,企业落地主流）→ **LoRA 微调**（改行为风格）→ **工具调用**（补短板,通向智能体）。
6. **推理模型**通过可验证奖励的 RL 学会"慢想",推理时多花算力换取硬任务的大幅提升——快慢双系统成为新常态。
7. **幻觉是机制性产物**:流利＝自信≠正确。评测要警惕污染与刷榜,关键事实必须核实。清醒认知短板,才能把 LLM 用在刀刃上。

## 思考题

1. 用"压缩即智能"的视角解释:为什么在小说语料上把"凶手是__"预测准,需要的能力远超记忆?
2. 基座模型对"中国的首都是哪里?"可能不直接回答而是续写出别的考题。用"文本分布模拟器"的概念解释这个行为,并说明 SFT 改变了什么。
3. RLHF 为什么用"排序"而不是让标注员直接写满分答案?谄媚倾向是如何从这个机制里长出来的?
4. 思维链为什么能提升数学正确率?从"每个 token 的计算量固定"这一架构事实出发解释。
5. 你的公司要做一个基于内部规章制度的问答机器人,制度每月更新。你会选微调还是 RAG?为什么?
6. 幻觉能通过"更大的模型+更多的数据"彻底消除吗?结合幻觉的三个机制性根源给出你的判断。
7. 推理模型在数学竞赛上进步巨大,但在"写一首好诗"上收益不明显。从"奖励是否可自动验证"的角度解释这种不均衡。
